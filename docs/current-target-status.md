# 目标工作模型交接状态

2026-11-16，当前版本 v0.3.111。R4 在 `6b00957` 加 R3 工作区的基础上收敛生产入口，R5 完成重启加载评估。

已完成：R0 的 42 份冻结基线；R1 来源目标捕获；R2 共享只读目标视图、旧修改重放、编辑目录复用、版本失效和闲置淘汰；导入/刷新/原文编辑接受后的应用服务预生成。资源准备/刷新中的来源等待，同 ID 连续版本合并，页面共享一次读取；缺失/空文件明确报错。

R3 编辑列表直接投影共享目标快照。单一、可编辑的目标分支绑定到 format_version=1 的来源锚点。重复、复杂和不可映射分支保持只读。未启用和当前无法应用的修改记录仍可管理与撤销。

预览、保存候选和运行编排共享可复用的源规则分支。运行组合仍准备本次配置的出口、DNS、provider、全局和网络上下文。保存核对来源文件和记录修订、个人修改修订及规则集库修订，提出的修改通过候选检查后才写入设置。

R4 的编辑器从只读页已生成的规则投影准备操作权限和个人修改记录。刷新使用编译器共用的来源锚点适配器，次来源也会在准备候选前校验旧修改。运行编排在来源精确匹配时从同一快照重放修改。旧的规则投影独立保存在回归目标中，作为历史对照。

R5 在 Linux Release 独立进程中测量原文重建和 JSON、CBOR 磁盘产物。5 万条 Clash 规则就绪中位数由 302.91 ms 降到 104.10 ms（JSON），原生配置收益较小。当前重启继续从原文准备内存快照。若真实订阅首次打开验证同样的收益，优先试行大型自包含 Clash YAML 的 JSON 缓存。方法、限制和生命周期见 [R5 证据](evidence/2026-11-16-target-r5.md)。完整阶段见 [规划](rule-document-plan.md)，检查见 [L1/L2/L3 状态](l1-l2-l3-status.md)。

R5 后续在 Linux Release 应用中观察到，1 万条规则可由启动预生成覆盖，5 万条的快照超出 32 MiB 闲置预算。应用现在将估算过大的来源延迟到页面请求。5 万条样本等 1 秒再打开时，完整读取从两次降为一次。250 ms 打开时，完整转换等待移到点击后。生产磁盘缓存仍待按需加载试点。见 [预生成预算复测](evidence/2026-11-16-target-r5-prewarm-budget.md)和[规则页加载契约](subscription-personal-rules.md#规则页加载与缓存)。
