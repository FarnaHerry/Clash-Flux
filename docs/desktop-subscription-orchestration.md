# 桌面订阅编排：最终架构目标

状态：**L3 的固定分层与桌面 Clash 多来源编排已接入代码**（2026-10-01）。
本文件同时保留最终架构目标；当前支持范围和未完成部分见 §7。
内核能力与保真度判定以 [sing-box 分层契约](singbox-layers-and-fidelity.md) 为准。

## 1. 产品语义与平台范围

桌面端允许一个主订阅和多个次订阅同时参与运行。主/次是**运行角色**，不是文件格式：
Clash YAML、sing-box JSON、OpenVPN、PPTP 及未来接入的端点可以成为连接来源；
能否承担默认出口，由平台权限、协议及完整路由能力决定，不能仅按类型名称承诺。

- **主订阅**：唯一默认来源，提供默认出口和默认订阅规则。未命中显式分流时走它；
  主订阅内部的 selector/urltest 继续保持内核原生语义。
- **次订阅**：同时加载，导出可被规则引用的连接、节点或组；只有显式规则或用户
  明确启用的局部规则范围才把流量交给它。次订阅的 MATCH 不得接管全局默认出口。
- “保存了订阅”“加入当前编排”“作为主订阅”“选中查看/编辑”“内核实际运行”
  是不同状态，不能继续挤在一个 `selected` 布尔值里。

| 平台 | 最终产品范围 |
|---|---|
| Windows / Linux / macOS | 开发主订阅 + 多次订阅编排；逐项声明协议和权限限制 |
| Android | 保留单个活动代理订阅，可保存和切换多个订阅；不增加普通代理多订阅编排，不扩大现有原生辅助连接上限 |
| iOS | 按 TODO 暂缓；未来恢复时仍遵守手机端单活动代理订阅约束 |

平台能力控制所有写入口（UI、CLI、导入及持久化校验），不能只隐藏按钮。
**不能按窗口宽度判断能力**：桌面窄窗口仍是桌面，手机横屏/平板宽布局仍不开放编排。
共用的 DNS、路由与协议转换改进可在各平台使用，它们不等于增加手机多订阅功能。

## 2. 当前实际行为

- 普通订阅的排他 `selected` 仅代表唯一 main，不再代表全部参与来源。
- 桌面从启用的编排规则推导次来源；仅载入被引用的对象和其组成员、detour、DNS
  依赖闭包。保存但没有启用规则的普通订阅不进入运行配置。
- 次来源自己的订阅规则和 providers 不拼接到全局；MATCH 只声明默认导出目标。
- 原生 PPTP/OpenVPN 内网 CIDR 进入 SourcePolicy 层；连接仍由现有操作建立，
  规则引用不会自动拨号。原生连接无规则时不导出到核心配置，已手动拨号的系统会话
  不因编译而自行关闭。
- 不可用目标保留匹配条件，默认生成 reject；可明确选择主默认出口或 DIRECT。
  这项失败语义也用于旧规则迁移，原来的“省略后继续匹配”不再沿用。
- Android/iOS 不加载普通次来源；领域校验拒绝引用其它已保存普通订阅的启用规则。

## 3. 模型边界

以下表格描述最终概念。当前以 RouteRule / VpnPolicy、ProfileSource、CompileOptions /
CompileResult 落地主要边界；尚未建立独立 ProfileBinding 表。

| 对象 | 责任与身份 |
|---|---|
| ProfileSource | 持久化订阅来源、格式、下载策略、凭据引用和内容版本；稳定 profile ID |
| ProfileBinding | 是否加入编排、主/次角色、导出的路由目标及局部规则策略；引用 source ID |
| RouteTarget | 指向 profile ID + 对象种类 + 稳定对象 ID；涵盖组、节点、原生端点及系统连接 |
| RoutingPlan | 唯一主 binding、多次 binding、全局规则、不可用目标策略和修订号 |
| CompiledPlan | 一份完整 sing-box 配置、平台补偿动作、来源到内核 tag 的映射、保真度账本 |
| RuntimeSnapshot | 当前实际应用的 plan revision、连接状态和内核选择；由唯一数据泵发布 |

SQLite 的 schema 迁移保留旧订阅：旧 selected 迁成唯一主 binding，其它普通订阅
保持已保存而未加入编排；原生辅助连接按既有配置迁移，不凭空启用更多连接。
手机不能因为读取桌面同步数据就开启多订阅；遇到不适用的计划应返回明确的能力错误，
保留导入内容供查看/导出，不能静默删库或随意选一个生效。

配置意图属于持久化模型，实际状态属于内核/系统快照。用户动作成功时写透应用模型，
失败按修订号与目标校验回滚；页面不再创建第二份权威状态。

## 4. 编译与隔离契约

1. **一个计划、一份配置、一个内核运行时**。普通代理、原生端点进入同一个 sing-box
   配置；PPTP 等系统补充连接仍走平台 backend，不为每条订阅另起内核或 TUN。
2. 使用稳定 source/object ID 构造内部 tag 命名空间；显示名可以重复、重命名。
   重写所有已支持的引用：组成员、detour、DNS server/resolver、rule_set、规则目标、
   endpoint 等。未知引用字段拒绝并记账，不能用文本替换猜测引用。
3. 主订阅负责默认出口与订阅规则。次订阅默认只导入明确支持的节点、组、端点和
   依赖；次订阅规则如要启用，必须显式规定匹配范围和顺序，不隐式拼接各自 MATCH。
4. 入站、TUN、混合端口、日志、控制面及应用缓存只有一个托管所有者。
   主订阅 DNS 作为默认策略；次订阅 DNS 可作为有命名空间的显式依赖，不能覆盖
   全局 DNS。多个 JSON 的其它顶层项没有默认“merge”语义，须逐项定契约和记账。
5. 路由顺序：内核前置动作 → UserOverride → SourcePolicy → 模式规则 →
   MainPolicy → MainFallback。普通次订阅不自动吸收流量；层级不能被权重跨越。
6. 组内自动选择由 urltest 完成、手动选择仅 selector。节点选择和缓存按稳定组身份
   保存，切换主订阅不清除次订阅选择；对象删除或类型改变时显式失效。
7. 保真度账本增加来源定位（source ID + 原始对象名），避免同名订阅无法定位问题。
   原生 JSON 能导入不代表任意顶层项都能参与编排； unsupported 必须可回看。

### 不可用目标策略

最终形态中，每条显式分流规则拥有明确的失败策略。默认 **阻断**；用户可显式选择
回主订阅或直连，并应看到这会改变出口。被禁用、缺失、连接失败的目标不会因为编译时
省略规则而无声落到默认线路。主动禁用/删除被引用目标前，展示受影响规则。

“内核停止”也须定义：系统代理取消和 TUN 退出后应用不能声称仍阻断宿主机流量；
启用系统补充连接是否保持及如何恢复按其所有权契约执行。此状态必须与“内核运行但
次连接不可用”区分；不能在 UI 假装有系统级 kill switch。

## 5. 原子应用与交互

一次操作经过：准备源内容/凭据 → 编译完整候选计划 → 固定版本内核配置检查 →
准备平台补偿动作 → 应用内核配置 → 核对运行状态 → 提交新计划 revision。
失败保留旧有效内容、计划和配置，撤销本轮拥有的平台动作；重启型应用不能承诺连接
零中断，失败要明确反馈。网络、检查、路由和启停均在任务线程执行。

刷新次订阅按稳定身份保留规则引用，缺失对象进入错误/不可用处理，不偷偷选首个
同名节点。快速连续操作只提交仍匹配当前目标 revision 的结果。

桌面订阅卡片区分“主订阅”“已加入分流”“已保存”；设置主订阅和加入/移出分流
使用不同动作。规则编辑器先选来源，再选导出目标，同时设置不可用策略。
代理页按来源浏览真实组状态；连接详情能追溯命中规则与来源。保真度明细按来源定位。
不增加“内核未运行，请去设置启动”类常驻横幅。

官方 GUI 的状态交互可参考[研究记录](singbox-official-gui-review.md)，多订阅角色与
计划编译是 Clash-Flux 自己的产品抽象，不能说成内核或官方 GUI 已自带的能力。

## 7. 已实现的 L3 重构

### 固定层级与同层顺序

| 层级 | 职责 | 当前生成方式 |
|---|---|---|
| UserOverride（3） | 用户全局覆盖 | 规则编辑器可选；旧规则迁移到此层 |
| SourcePolicy（2） | 次来源显式分流、原生内部 CIDR | 规则编辑器可选；内部 CIDR 自动产生 |
| MainPolicy（1） | main 订阅原有规则 | 按原始订阅顺序保留，用户不能在全局规则里伪造此层 |
| MainFallback（0） | main 的默认出口 | 使用 route.final；MATCH REJECT/DROP 用终结 reject 动作表达 |

排序比较固定为 **tier 降序 → priority 降序 → order 升序**。上移/下移只改变同层同权重
的先后，不覆盖优先级。内部 CIDR 在同优先级下保留最长前缀优先，并排在显式规则之后。
前置 sniff / hijack-dns / resolve 保持内核动作；现有模式规则仍在显式编排之后，
因此全局/直连模式也保留显式分流。这项顺序没有悄悄改成“模式覆盖一切”。

main 内部规则仍参与匹配，不能把整个 main 简化成一条 MATCH。
没有 MATCH 时保留现有首个 selector / DIRECT 默认策略；显式 MATCH,DIRECT 不改成代理。
原生 JSON 的 final 为空时使用第一出站，与
[官方 route.final 语义](https://sing-box.sagernet.org/configuration/route/#final) 一致。
“主默认出口”失败策略直接使用该默认目标，不重新跑 main 内部规则链。

### 引用与来源隔离

RouteRule 持久字段新增 id、tier、enabled、unavailable、target_kind、target_object、order。
来源仍用稳定 profile-N；对象用 **来源 ID + 类型 + 来源内原始唯一名称** 引用。
订阅显示名可改；组/节点原始名称改动会使引用失效，不匹配别的来源的同名对象。
当前还没有为源文件对象建立独立 UUID 注册表，不能承诺对象改名后自动追踪。

Clash 生成的 outbounds、DNS servers、rule_sets 使用 source ID + 对象名的可逆 hex tag。
已支持的组成员/default、detour、domain_resolver、DNS detour、route/DNS rule 引用一并重写。
两个来源的同名组/节点可以共存；跨来源原始 dialer-proxy 引用仍未开放。
原生 JSON 主来源保留未知字段及原有 tag，并检查生成次来源与出站/端点/DNS tag 的冲突；
不会猜测原生未知字段的引用关系。

CompileResult 输出 sourceObjects 和 participatingSources，保真度条目增加 sourceId。
代理页、托盘、首页与连接链路使用可读名称，API 和选择持久化继续用内部 tag。
旧的无来源选择键只迁移给当前 main；次来源不继承其它订阅同名组的历史选择。

### 持久化与应用

- vpn.global_policy 升级为 format_version=2。没有版本的旧数据按 v1 读取，保留旧权重、
  匹配类型排序和列表顺序；下一次保存编码 v2。未知字段、无效枚举、未来版本报错，
  不静默清空。SQLite 表结构未改变，user_version 保持 1，订阅数据不删除。
- policy.revision 表示规则意图版本；桌面 CoreSnapshot.planRevision 是成功应用后的
  运行序号（routing.applied_revision），主切换、内容刷新和重启均重新赋号。
- 桌面候选经完整编译及固定内核 `check -c ... -D ...` 后才停止旧内核；检查进程有超时，
  Windows 后台静默启动。候选与订阅文件关闭检查后再替换，不先删除 Windows 旧文件。
- 启动失败尝试恢复本进程记录的上一份来源内容与选项；旧原生接口或传输地址已变时
  禁止恢复旧引用。文件/选择/规则应用失败分别恢复旧内容、主选择和策略。
- 接管驻留内核时比较配置；配置不同则重启本应用拥有的进程，不能把新计划标成旧实例
  已经应用。预览目录与运行目录分别保存，预览不会覆盖正在运行的来源映射。
- 主来源、启用规则引用的来源、具有内部 CIDR 或仍连接的原生来源不能直接删除；
  先更换 main、解除规则或断开连接。新增导入不会继承 selected。
- Android 继续由后台 libbox 启动流程检查配置，没有桌面 CLI 预检查或普通多来源编排。
  尚未增加手机异步启动失败的完整计划回滚机制。

运行序号和文件替换不是跨 SQLite/文件/系统路由的持久事务；尚无崩溃恢复 journal。
跨进程重开的上一份原始内容也尚未持久保存，因此不能承诺异常退出后的完整计划回滚。
重启会中断连接；这些限制不能用“零中断/完全原子”描述。

### 桌面操作方式

1. 导入/保存 main 和次来源，将一个普通订阅“设为主订阅”。
2. 在规则页“全局路由”新增规则，选来源、匹配条件、来源分流或全局覆盖层。
3. 选择默认出口，或填写该来源内的原始组/节点名；保存时核对对象存在。
4. 设置层内优先级和不可用策略。禁用最后一条引用后，该普通次来源不再导入。
5. 代理页真实 selector 可手动切换，urltest 保持内核自动选择；标签带来源名称。

手机目标列表只有活动普通订阅和允许的原生连接。桌面窄窗口仍可以使用多来源。
CLI 的 profile use/update/remove 同样经过领域校验；目前编排规则编辑入口在 GUI。
