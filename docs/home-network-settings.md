# 首页系统代理与虚拟网卡设置（2026-11-04）

首页齿轮及设置页共用 NetworkSettingsEditor、SettingsModel 和 CoreModel 操作门禁。
桌面宽屏使用可滚动弹窗、固定底部动作；Compact 使用二级页，Android 仅展示本地监听与
虚拟网卡能力。首页接管开关仍独立，系统代理与 TUN 可以同时开启。

## 内容分组与编辑交互

- 系统代理分为“系统接管 / 本地监听 / 访问控制”：代理方式、目标及 PAC 参数同组，
  绕过与退出恢复分别成组；监听标签集中端口、地址与绑定接口；访问控制集中 LAN、
  客户端网段和认证。自定义 PAC URL 隐藏本应用的代理目标，保留草稿值。
  Android 的本地代理只展示后两个标签。
- 虚拟网卡分为“基础 / 接管范围 / UDP”：基础集中网卡参数、DNS/地址族及路由保护；
  接管范围集中路由方式、目标网段、IP 规则集和平台来源筛选；UDP 集中会话管理与 NAT。
  名称/地址及 Linux 筛选使用展开行，筛选行显示当前模式，有已有自定义值的组默认展开。
  平台能力限制仍遵守下文约束，桌面窄窗不裁除 Linux 或规则集能力。
- 编辑器内部平铺字段，不套分组卡片；标签已说明用途时移除重复标题，靠字段间距和留白组织信息，宽屏与窄屏共用此结构，详见 [平铺表单](ui-development.md#弹窗与平铺表单)。
- 标签栏与底部动作固定，每个标签独立滚动并保留位置，共用整份 NetworkForm 草稿。
  参数逐项排列，字段旁显示校验结果，错误标签显示标记；未通过校验不能提交。
  窄屏在标题栏右侧提供保存图标，有「保存并应用」时从该图标菜单选择；返回、Esc/系统返回及弹窗遮罩关闭请求统一检查未保存修改；
  选择继续编辑保留草稿，放弃不写入，保存成功发布共享模型后再关闭。提交期间阻止重复关闭。
  窗口宽窄切换保留当前编辑路径、标签、草稿和滚动，不重新打开或另建一份设置。
- 设置页入口分组和“更多”的侧栏收纳规则见 [UI 开发约定](ui-development.md#响应式与平台边界)。

## 保存与配置来源

- 网络表单统一暂存：端口、LAN、IPv6、MTU 和全部高级参数只在保存时提交，取消不写入。
  旧即时 LAN/IPv6 写入口已移除；环境变量 shell 选择仍是独立的 UI 偏好。
- 新权威键 core.network_settings 保存 format_version=1、revision 及整个表单；没有新值时
  从旧 core.* 键读入，不启动写迁移、不删旧键、不改 schema 或订阅原文。未知字段、未来
  版本、类型错误明确拒绝，错误不回显凭据；单 key flush 不会落下一半表单。
  本轮的 advanced 为可缺省扩展对象，旧 v1 不缺其它必填字段即可原样读入；扩展对象内部
  仍严格检查完整字段，新写入不会回写旧字段键。
- 新高级参数缺省跟随来源；监听端口、监听地址、认证、MTU、路由范围和 UDP 会话上限
  有显式覆盖开关。原生 JSON 的其它字段保留。严格路由继续由应用管理。
- 保存经应用任务在工作线程取得生命周期锁，核对整份基线（含 revision）、参数、完整候选
  和固定内核检查。失败保留设置与表单草稿；页面离开不取消已提交任务。配置意图不冒充运行态。
- 保存只记录下次连接/重启使用的参数；连接中可以保存并应用，复用候选交接和旧计划回滚。
  当前网络 revision 与已接受计划不同则显示待应用。Android 等待后台接收结果，失败恢复
  旧参数并尝试恢复旧计划；真实 VPN 路由和失败恢复仍需真机验收。

## 虚拟网卡

- 桌面 stack：跟随配置、system、gvisor、mixed；Android 维持 gvisor、strict_route=false。
- MTU 1280–9000，生成默认 1400；IPv6 是全局网络偏好，新生成 TUN 按该偏好配置双地址族。
- DNS 接管：跟随配置、native、hijack、disabled。原生/关闭模式的 TUN 不再匹配应用生成的
  通用 DNS 劫持前置规则，HTTP/SOCKS DNS 行为保留；来源自定义 DNS 路由不删除。
  dns_address、上游 DNS、FakeIP 与 DNS 分流仍属于来源 DNS 配置，不另造第二份 DNS 库。
- 网卡名称、IPv4/IPv6 地址（CIDR）；自定义接管/排除网段。空接管覆盖表示默认全流量，
  排除流量绕过内核与全局规则。原生 VPN 的传输地址和自有回环补偿继续追加，不能被用户
  排除覆盖撤销；Windows PPTP 与自定义接管路由的已有不兼容检查保留。
- UDP 使用当前 udp_timeout、udp_mapping、udp_filtering、udp_nat_max，不生成失效的旧
  endpoint_independent_nat 或 GSO。会话上限 0 使用内核默认。
- Android 应用模式：跟随、全部、仅选中、排除选中。提供可见应用选择和手动包名；只查询
  launchable/系统可见应用，不申请 QUERY_ALL_PACKAGES。保留不可见但已填写的包名，后台
  对不存在的应用明确失败，不静默扩大接管；本应用保留物理网络通道。
  自定义路由不再因缺少另一地址族的路由而补成该地址族的全流量接管。

## 系统代理与本地监听

- 系统目标选择实际已接受配置的唯一混合/HTTP 入站，使用真实端口、回环地址，不使用尚未
  应用的表单端口。带认证或绑定非回环接口的目标明确拒绝，不假装系统能自动提供凭据。
- 支持原生绕过列表；按各系统语义匹配，不能将其称为跨平台一致的规则或 CIDR 分流。
- 原代理与写入后的完整快照保存于 proxy.system_lease。仅在当前状态与本应用写入快照
  完全相符时撤销/恢复；其它用户/客户端修改（包括绕过列表）不覆盖。关闭恢复选项则仅
  撤销接管。重配允许重新接管刚刚释放的同一快照，不能抢占另一次外部修改。
- GNOME/KDE 保留模式、监听与绕过设置；Windows 使用用户会话 WinINet 连接配置保存
  手动/PAC/自动发现标志；macOS 保留各网络服务的手动及自动代理状态。macOS 旧代理若带
  无法回读的认证凭据，先拒绝接管，避免丢失凭据。系统变更不由内核或 root 服务重复执行。
- 本地监听支持端口、监听 IP、绑定接口、用户名/密码及客户端 CIDR 白名单；白名单仅作用于
  mixed/HTTP/SOCKS，先于分流规则执行且始终允许回环；原生来源无唯一 tag 则拒绝该覆盖。
  密码保持原文，原生认证不覆盖时保留；用户显式空认证才删除。

## Linux 路由增强

- 自动重定向显式启用后使用固定内核的 auto_redirect/nftables；缺省仍采用策略路由，
  iproute2_rule_index=9000 保留原生 VPN 补偿协议。来源启用了重定向但应用未明确开启时，
  覆盖记 Field/Approx；启用后若有已连接原生 VPN 或非零 routing_mark/default_mark，
  拒绝整份候选，保留原计划。内核/系统不支持 nftables 时明确失败，不静默切换模式。
- 接口、用户 UID/UID 范围和 MAC 分别选择仅选中或排除选中；显式覆盖会清除来源的
  同组筛选，关闭覆盖则保留原生参数。UID 范围用起始:结束，当前表单接受 0–2147483647；
  MAC 仅在自动重定向开启时可用。上述参数仅开放 Linux 桌面，不因窗口变窄隐藏。
- 筛选发生在进入内核之前，不能把排除项称作全局规则中的 DIRECT；排除流量不执行
  代理分流。Android 继续使用应用包名选择，不开放桌面 UID/接口/MAC 参数。

## IP 规则集接管

- Linux/Windows 可直接选取全局资源库中的规则集，分别用于接管和排除。保存稳定资源 ID，
  编译后解析为真实命名空间 tag；支持导入的 inline 集与 remote source/SRS 集。
  仅提取目标 IP CIDR，域名、进程、源地址和其它条件不参与系统路由，逻辑组合也不能当作
  完整的防火墙策略。与手动接管网段取并集，排除优先；Windows PPTP 共存仍拒绝规则集路由。
- 未启用 TUN 时校验引用但不为它载入资源；规则集不需要再被全局分流规则引用。
  缺失 ID 拒绝候选；资源库列出虚拟网卡引用并阻止删除，关闭 TUN 或关闭覆盖不解除已选资源的引用保护，需要先取消选择再删除资源。
- 接管集合额外带两个未指定地址的主机路由（0.0.0.0/32、::/128），防止集合没有 IP
  或缺少某个地址族时触发内核默认全流量路由。这些地址不表示可用的业务目的地址。
- 策略路由模式在启动时展开 IP 集合，远程集更新后需重新连接才能刷新系统路由；
  auto_redirect 的地址集合由原生更新回调刷新。手动刷新复用已有候选重启和回滚。
  macOS/Android 客户端不开放此能力；订阅内的普通域名规则集仍可用于内核分流。

## PAC

- 系统代理方式包含手动代理、本机 PAC、自定义 HTTP(S) PAC URL。仍由用户会话修改
  系统设置，服务内核不写第二份代理设置。GNOME/KDE/WinINet/macOS 自动代理设置均
  纳入原快照、写入指纹和恢复；后续外部修改会阻止本应用覆盖它。
- 本机 PAC 只监听 127.0.0.1，可配置端口，使用随机路径与 Host 校验；最多 8 个活动
  连接、8 KiB 请求头、2 秒截止，不处理上传、WebSocket 或文件目录。只发布生成的
  FindProxyForURL，不执行用户脚本，不把订阅规则翻译成 JavaScript。
- 回环和显式直连域名返回 DIRECT；精确主机、通配符、以点开头的根域及子域可用，
  不支持 CIDR。其它请求返回已接受 HTTP/混合监听的 PROXY，不添加失败直连兜底，
  分流继续由内核执行。系统自身或不遵循 PAC 的应用仍可能有不同的网络行为。
- 服务先成功监听才写系统 URL；失败恢复原设置，释放系统接管后停止服务。异常退出
  的遗留所有权由已有启动清理处理；未持有本机 PAC 服务时不能显示为实际接管成功。
  单独执行后退出的 CLI 不能开启本机 PAC，可由常驻 GUI 接收转发命令，或使用外部 URL。
- 自定义 URL 由操作系统/应用下载执行，应用不预取、不绕过系统 TLS 校验，也不能保证
  脚本选择的其它代理受本应用规则约束。拒绝 URL 中的凭据、片段和控制字符。

## 验证

sysproxy 在有 Node 的环境还会执行生成的 JavaScript，检查直连例外与无直连兜底。
日常检查遵守[测试技能](../project-skills/clashflux-test/SKILL.md)。Linux 还可执行：

```bash
cmake --build build --target clash-flux test_singbox test_sysproxy
ctest --test-dir build --output-on-failure --no-tests=error -R '^(singbox|routing|sysproxy|resource_management_runtime|cps_dependencies)$'
python tests/test_network_capture_runtime.py
```

最后一个是独立的可选运行回归，需要 bwrap/ip/nft、/dev/net/tun 和非特权用户命名空间。
缺前提明确失败，不向宿主申请 root，不安装服务；内部创建独占用户/网络命名空间和临时
数据目录，验证双栈接管/排除、纯域名空 IP 集防扩大、nftables 建表以及停核后的清理。
此检查不等于真实网卡网关、上网性能、原生 VPN 共存或 Windows/macOS 系统设置验收。
实际证据见[主线状态](l1-l2-l3-status.md)，运行态见[桌面生命周期](desktop-proxy-lifecycle.md)。
