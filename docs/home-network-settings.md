# 首页系统代理与虚拟网卡设置（2026-11-03）

首页卡片及托盘将「TUN 模式」显示为「虚拟网卡」；内核 TUN 类型、配置键和 CLI tun 命令保持稳定。
齿轮与启停开关独立。桌面 Medium/Expanded 打开弹窗，Compact 进入二级页，保存/返回保留父页。
手机不因此获得桌面系统代理或多来源能力。

## 系统代理

复用 SettingsModel 的混合/HTTP/SOCKS 端口设置、局域网接入和环境变量复制。
混合端口必填，HTTP/SOCKS 可留空禁用；有效端口 1–65535，各启用监听类型不得重复。
全部端口校验通过才写缓存，过期表单不覆盖已变化的端口。新端口重启内核后生效，
环境变量复制仍读取实际运行端口；保存表单不启动代理、不调用系统代理启用动作。
局域网及环境变量 shell 选择沿用设置模型的即时保存行为，端口字段由保存按钮提交。

## 虚拟网卡

- MTU 接受 1280–9000 的整数，默认 1400；输入无效禁用保存，编译边界再次检查。
- 严格路由使用 sing-box 原生 strict_route，桌面默认 true；IPv6 沿用已有全局设置写透，
  影响 DNS/入站，非仅作用于虚拟网卡。MTU/严格路由保存后重启内核生效，IPv6 开关即时保存偏好。
- MTU/严格路由提交由应用任务执行，生命周期锁在工作线程等待；全应用单飞，离页仍完成，
  结果回 UI 发布。提交前检查原设置，拒绝过期表单；动作不启动或重启内核，不改变接管开关。
- 持久键为 core.tun_mtu / core.tun_strict_route；不改数据库 schema，不改已有订阅。
  原生 JSON 的 MTU 在没有显式应用覆盖时保留；用户保存 MTU 后才对导入 TUN 应用该覆盖。
  严格路由继续由应用控制，Android 在首次编译前按平台策略强制 false，gVisor 策略不变。
