# 订阅个人规则

订阅原文、个人修改和生成的 sing-box JSON 分开管理。订阅更新只替换原文；
个人修改绑定稳定 profile ID，切换主订阅不把它们带到其它订阅，也不生成中间 YAML。

## 页面与使用

- 规则页只读：只保留「订阅规则 / 全局规则」两个分区，展示当前主订阅经过个人修改后的
  实际规则和已保存全局规则；不提供搜索、原始/生效/个人视图切换、规则集分区或行内编辑。
  订阅卡片右键「编辑规则」在 Medium/Expanded 打开规则弹窗，Compact 进入该订阅的
  独立二级编辑页；全局规则从规则页页头「管理全局规则」进入独立二级页。全局规则的目标来源下拉在订阅连接之外提供「直连」；
  选择后规则直接落到 DIRECT 出站（原生引擎返回系统默认路由），不使用来源对象、
  不可用策略或原生补偿路由。
- 订阅规则来源只列支持个人规则的 Clash YAML 与原生 sing-box JSON；PPTP、OpenVPN 和无可读来源文件的记录直接过滤，卡片也不提供「编辑规则」。默认选中可编辑的主订阅，否则选择首个可编辑来源；来源删除或变成不支持的格式时重新选择，没有可编辑来源则显示空状态，不保留无效选项或“不支持编辑”占位。此筛选只作用于订阅规则编辑，不限制全局规则的连接/出口目标。
- 编辑列表展示修改后的目标规则，标记订阅原有、个人新增、已替换和已禁用；
  未启用或未应用的个人修改保留在列表尾部，可启停或撤销。原规则禁用/替换可以恢复，
  个人新增可开关、删除和同位置排序。
- 宽窄屏列表共用紧凑两行：首行显示匹配类型、匹配内容和出口，次行显示状态与适用的插入位置；右侧只保留操作按钮。
  文本按实际分配宽度单行省略，完整值保留在提示、无障碍标签和详情中；列表保持规则顺序与虚拟化。
- 结构化编辑支持精确域名、域名后缀、IP/CIDR、域名关键词、域名正则、进程名称和个人规则集引用。
  复杂逻辑、订阅原有规则集及带额外修饰符的原规则保留原文、只读展示，不有损转换成简单条件。
- 新规则可插在订阅规则之前或订阅兜底之前；默认出口单独修改。不会把追加规则放到
  MATCH 后面。出口选择本来源对象、DIRECT、REJECT 或 REJECT-DROP。
- 新增/编辑规则在 Medium/Expanded 使用弹窗，Compact 使用二级页面；两者共用表单与
  保存回调，保存失败保留表单。来源选择行到列表、
  页签到内容使用与规则卡片间隙相同的 4pt 密度，不为隐藏的提示保留空占位。
  手机仍只有一个活动普通来源，不开放普通多订阅编排。
- 编译 JSON 预览只读生成指定来源及个人修改，不启动内核，不发布运行/代理预览映射；
  不等于正在运行的完整全局计划。Compact 使用独立二级页面，返回直接父页，文档占满说明下方的剩余空间；
  非 Compact 使用弹窗，两者均支持复制。文件高级编辑仍直接改原文，远程更新会覆盖它。

## 规则页加载与缓存

普通只读页与编辑列表共享 sing-box 来源目标基线，按[目标工作模型规划](rule-document-plan.md)推进。目标字段与启用/修改标记分开。编辑操作使用快照内的目标身份，提交时绑定到原有个人修改格式。

普通规则页、订阅规则弹窗和二级编辑页共用 `ProfilesModel` 的不可变快照。按 profile ID 隔离，输入身份包含版本化文件、类型/名称、已接受记录的来源代次、个人修改、规则集目录和外部资源修订。数据泵只在相关输入变化时失效；模式/TUN、流量和无关设置不重新解析。DataSession 的多行统一选择修订不改变来源代次；无法区分用途的单行记录修订保守重验证，不能为省略任务漏掉同文件的已接受刷新。

缺少快照时由应用任务在工作线程准备一次。读取、转换、目录和发布共用 `profile_rules_snapshot.cpp` 应用服务，页面只申请或引用快照。已加载列表在重新验证期间继续显示，编辑动作等待当前版本就绪；发布前检查输入与任务版本，删除/重建、ABA 和旧任务晚到不能覆盖新数据。失败明确显示错误、可重试。资源准备成功会重试对应来源的视图，手动/周期外部资源更新推进资源修订。

只读页和编辑器共享 `TargetSourceModel` 生成的规则投影。编辑器按需补充操作权限与修改记录。重放旧个人修改时使用来源锚点和已转换载荷，默认动作独立展示，复杂原生对象保留 JSON。新建禁用或替换操作要求目标与可编辑原规则唯一对应。重复、复杂及丢失映射的目标只读。目录直接复用模型内的来源对象，准备期间显示只读规则并暂停编辑。发生冲突时保留已保存修改供恢复。

`CoreStore::profileTargetSource` 只用明确内容、来源身份、固定转换默认与资源根，不继承当前模式/TUN/监听/全局修改，不下载、不批准候选、不改运行追溯。其弱索引以完整输入加资源修订核对，最多 4 个键、键预算 8 MiB，不另外强持有模型。冷转换在任务线程与资源提交/回滚串行，避免保留失败应用的临时资源。依赖 file/GEO 或未固定正文的 HTTP provider 时不命中弱索引，重建时重新读取；现有 file provider 仍不监听文件修改。

页面缓存共同计入原文、修改/目录输入、目标模型、只读投影及懒编辑投影，闲置预算 32 MiB，按最近访问淘汰整个闲置条目。页面挂载时固定正在使用的快照；最后解除固定后执行淘汰，外部已持有对象继续有效。内存计费在任务线程预计算，UI 发布不扫描整张规则表。预算是闲置保留边界，不是进程 RSS 上限：大来源在用/转换中可以超出，超过预算的条目离开后重进需要重新准备。未淘汰的重进不读取原文、不转换；个人修改变化复用仍存活且依赖身份完整的目标基线，再生成视图。

虚拟列表直接引用拥有型快照，编辑器按需生成投影并共享原文和目标数据。导入、刷新或原文编辑被接受后，既有订阅泵按修订排入预生成队列，导入资源准备完成后推进对应来源。资源准备或刷新中的 ID 等待，同一 ID 合并到最新版本，首次 hydrate 只预生成一个默认可用来源。队列复用页面单飞、版本核对及同一 32 MiB 闲置预算。文件缺失或为空明确报错。配置预览、保存检查和运行编排可借用同一弱索引中的目标快照，核对来源身份及完整原文，复用可直接生成的规则分支。规则提供者、带诊断或需重新解析出站引用的规则由当前编译上下文处理。测量和覆盖见 [R2 证据](evidence/2026-11-16-target-r2.md)和[预生成接入](evidence/2026-11-16-target-r2-prewarm.md)。

预生成先在任务线程查看已接受版本的原文大小。文件超过闲置预算的 1/32（默认 1 MiB）时，等页面请求再读取转换。这个估算来自混合 Clash 规则样本，准确的内存计费和淘汰仍以生成后的对象为准。页面请求可以在大小查询完成前启动，并复用已在途的转换。读不到大小时由原有加载链路处理文件错误。

## 数据与编译契约

`settings` 的 `profile.rules.<profile-id>` 保存 format_version=1、revision 与 rules。
每条修改有独立 ID、operation、anchor、enabled、match、pattern、target、unavailable。
operation 为 prepend / before_final / replace / disable / final；不保存生成后的出口 tag。
目标按所属来源的原始唯一名称解释，随后由现有来源命名空间机制解析。

Clash YAML 规则与原生 JSON route.rules 使用编译器的共享解析投影。修改在源规则降低为
内核规则前应用；新增/替换规则直接生成 JSON。原生未知规则对象完整保留，不反向序列化 YAML。
固定顺序仍是前置动作 → 全局覆盖 → 来源分流 → 模式规则 → 修改后的主规则 → 主默认出口。
次来源不隐式导入内部规则；其个人修改仅在作为主来源时执行。

replace / disable 的 anchor 为带格式前缀的原始规则文本（JSON 使用规范化 DOM 文本），
不以列表索引定位。刷新后原规则必须唯一匹配；缺失、重复、冲突拒绝候选并保留旧内容。
个人修改记录视图仍可撤销有冲突的修改。显示名改名不改变 profile ID；原始对象改名
不自动绑定其它对象。出口失效保留匹配，按明确的 reject / direct / main 策略处理并记保真度；
main 使用原来源默认出口，不重新匹配来源规则，修改默认出口自身不能选 main 回退。

保存核对文件、来源记录版次、原文、个人修改 revision 和资源库 revision。活跃主来源走已有候选检查与重启路径，
其它来源独立编译检查。通过后写入修改设置，失败保留原规则设置；刷新冲突时保留旧文件。预览在同一来源版本上生成并移除控制面凭据。
刷新在资源准备前通过编译器共用的来源锚点适配器检查旧修改。次来源同样检查锚点，切为主来源时可以继续重放这些修改。
Android 继续由后台 libbox 做实际启动校验，未新增完整异步启动失败回滚或跨文件崩溃事务。

不修改 SQLite schema。个人修改写入时确保所属 profile 同事务存在；删除 profile 与对应
修改键同事务提交，settings/profile flush 串行，旧快照写入不能复活已删除修改。
未知持久字段、未知版本拒绝读取；原文中既有手动修改不猜测迁移，保持原样。

## 全局规则集资源库（2026-11-03）

按新的产品决定，在「设置 → 资源」二级页管理全局规则集，不在规则页增加资源分区。
沿用旧资源库数据、ID 与引用；全局表示可被不同订阅引用，不表示自动参与当前配置。
页面提供添加/导入、详情与引用、编辑、删除，以及桌面远程资源的单项刷新；全局与订阅
个人规则编辑器都可按资源名称选择，保存稳定 ID。宽屏表单为弹窗，Compact 为独立二级页，
返回资源列表保留父页；桌面非 Compact 内容限宽居中。订阅自带 provider 仍从卡片的
「外部资源」进入，两种资源的所有权和更新机制分开。

资源库为独立的 `settings["rules.resources"]`，format_version=1、revision、resources
经同一普通 TU 的严格 typed codec 保存，不变更 SQLite schema。资源 ID 与显示名分离，
个人规则 `match="rule_set"` / pattern 保存资源 ID；改名不改变引用。资源库供所有订阅选择，
当前主订阅的启用个人规则、或启用的全局规则引用的集合参与运行；同一集合只加载一次。
全局规则保存相同资源 ID，选择目标来源、组/节点、层级和不可用策略，切主订阅后继续生效。
界面显示资源名称，改名不改变匹配；不会自动应用未引用的资源。

- 远程资源接受 HTTP(S)、JSON source / SRS binary，更新周期为 1–8760 小时。
  编译生成原生 remote rule_set 和显式直连 HTTP client，TLS 保持系统校验；
  下载、运行期定时更新与缓存归 sing-box。保存地址仅校验声明，不表示远端已下载或可用。
- 本地手写内容接受 sing-box 规则集 JSON（version 1–5 + rules），
  单份 8 MiB、内容总计 16 MiB，资源最多 256 个。内容独立保存、编译为 inline headless rules，
  不继续引用原文件，不改文件；逻辑子条件保持原生对象，未知条件由固定内核拒绝。
- 桌面可导入本地 SRS：先有界读取独占快照，再由固定内核 `rule-set decompile` 转为 JSON，
  保存为同一 inline 资源。输入和输出各限 8 MiB，工具限时 15 秒，失败保留表单与原资源；
  不解码未知未来版本，不忽略不能反编译的 AdGuard 二进制条件。只清理本次独占暂存目录。
  Android/iOS 不启动桌面工具，因此继续提供本地 JSON 和远程 SRS。
- 新增/替换的个人规则选择集合、目标与前置/兜底前位置，直接生成原生 rule_set 匹配。
  来源命名空间不改写资源库 ID；与原生订阅已有 tag 冲突拒绝，原有规则集保留。
  远程运行 tag 包含完整 URL/格式身份，修改下载地址不复用旧地址的原生缓存。
- 保存检查资源库 revision，先对全部资源生成独立候选并执行桌面内核检查，成功才写缓存；
  运行时重配失败恢复旧 setting，订阅/规则修改共用生命周期锁。未引用资源也验证声明和本地内容，
  远程内容仍在内核运行时校验。Android 完整校验仍由后台 libbox 执行。
- 删除扫描全部全局规则和现存 profile 的个人规则，包含已禁用记录；仍有引用则拒绝，
  订阅引用给出订阅名称。全局保存入口也检查资源存在，资源编辑和全局写入共用计划生命周期锁。
  删除订阅不删除共享资源；没有后台扫描、资源文件清理或订阅原文重写。

桌面远程资源菜单提供「重新下载（重启内核）」。固定内核没有规则集热更新/状态 RPC，
因此显式增加该资源的 `refresh_generation`，仅轮换它的原生缓存身份，经候选检查后沿现有
重启/恢复流程应用。旧缓存不删除；新下载/启动失败恢复旧资源声明和可恢复的运行计划。
正在运行且被启用规则引用时，只有内核重新就绪才显示「本次已重新下载并应用」；未运行或
未引用则只显示「已安排在下次引用启动时重新下载」。这是本次操作的会话内回执，修改库后清除，
不冒充原生周期更新状态或持久时间戳。手动更新会短暂停止当前内核，Android/iOS 暂不提供此操作。
GEO EOF 自动修复不删除共享 `cache.db`（其中还有个人/订阅资源与选择状态）；计划含非自有
文件资源时，不把无法归属的 EOF 当作 GEO 损坏，也不清理 GEO 文件，避免破坏旧计划的恢复条件。

当前未提供资源推荐目录、原生运行期定时更新时间/下载状态查询、
Clash YAML/text/MRS 导入此资源库，以及全局代理集合。订阅原有 provider 不导入该库，
由订阅外部资源页逐项刷新。
这些边界不影响既有 Clash provider 转换路径。修改 JSON 原文的高级入口不受此资源库管理。

运行回归可先用 `test_singbox --personal-rule-fixtures <独立目录>` 生成配置，再执行
`python tests/test_personal_rule_sets_runtime.py <同一目录> <固定 sing-box 路径> <OpenSSL 路径> <test_runtime_health 路径>`。
脚本只启动 loopback HTTP/TLS、SOCKS 与 echo 测试，不访问应用库、不启用 TUN 或系统代理；
最后一个参数调用生产 SRS 导入函数并验证源文件保留、坏输入/超限拒绝与暂存清理，随后验证导入结果的实际匹配。
脚本还覆盖全局引用、新缓存身份强制获取变更内容、同身份复用，以及离线恢复新旧缓存。
省略 OpenSSL 时不覆盖 TLS。`personal_rule_sets_runtime` 已注册到桌面必跑 CTest，使用独占临时目录，
强制传入固定内核、OpenSSL 和两个生产测试程序；缺失/禁用由 `project_test_gate` 拒绝。
手动命令可保留完整配置和日志证据；编译/codec/引用保护断言继续由 singbox / routing 覆盖。

## 外部资源识别

规则集中的外部引用属于订阅解析产物，不是用户手工维护的规则集。订阅解析现在识别：

- `rule-providers` 中 `type: http` 的规则集；
- `proxy-providers` 中 `type: http` 的代理提供者；
- `geox-url` 的 ASN/GEO 数据地址。

订阅卡片右键的「外部资源」展示名称、URL 与实际类型标签，不显示订阅名、底部数量提示或
宽窄标题栏刷新。HTTP rule/proxy provider 和受支持的 Geo DAT/MMDB 行提供单项刷新及单飞进度；
Geo DAT/MMDB 转换、geodata-mode、属性筛选、大小和独立调度边界见[Geo 资源](geo-resources.md)。
刷新走应用级任务与生产候选准备，使用完整来源/资源身份；只强制下载所选项，其他过期资源
复用已验证快照。其他必需资源尚无快照时拒绝操作并提示先应用订阅，不顺带批量下载。
下载前后核对来源原文，完整候选通过才替换缓存；检查失败保留旧数据，运行交接失败恢复
所选缓存与原运行计划。未运行/未参与时只更新缓存，不启动内核；桌面参与运行计划时应用
经检查的准备结果并保留待命/监听状态。Android 的异步重启不提前报告「已应用」。
列表没有原生周期下载时间/状态查询，不能据此判断尚未下载。
运行准备支持 HTTP proxy-providers 的 DIRECT 下载、验证缓存及 select/url-test 组
`use` / `include-all-providers` 节点展开，缓存与主订阅更新走同一完整候选检查。
