# 订阅个人规则

订阅原文、个人修改和生成的 sing-box JSON 分开管理。订阅更新只替换原文；
个人修改绑定稳定 profile ID，切换主订阅不把它们带到其它订阅，也不生成中间 YAML。

## 页面与使用

- 规则页分为「订阅规则 / 全局规则 / 规则集」。订阅分区先选来源，加号新增该来源的个人规则；
  全局分区新增全局规则，规则集分区新增共享资源。订阅卡片「编辑规则」进入相同页面。
- 默认展示修改后的规则，标记订阅原有、个人新增、已替换、已禁用；查看菜单可切换
  订阅原规则、个人修改记录。原规则禁用/替换可以恢复；个人新增可开关、删除和同位置排序。
- 结构化编辑支持精确域名、域名后缀、IP/CIDR、域名关键词、域名正则、进程名称和个人规则集引用。
  复杂逻辑、订阅原有规则集及带额外修饰符的原规则保留原文、只读展示，不有损转换成简单条件。
- 新规则可插在订阅规则之前或订阅兜底之前；默认出口单独修改。不会把追加规则放到
  MATCH 后面。出口选择本来源对象、DIRECT、REJECT 或 REJECT-DROP。
- 桌面编辑使用弹窗，Compact 使用独立页面；保存失败保留表单。非主来源显示
  「作为主订阅时生效」。手机仍只有一个活动普通来源，不开放普通多订阅编排。
- 编译 JSON 预览只读生成指定来源及个人修改，不启动内核，不发布运行/代理预览映射；
  不等于正在运行的完整全局计划。文件高级编辑仍直接改原文，远程更新会覆盖它。

## 数据与编译契约

`settings` 的 `profile.rules.<profile-id>` 保存 format_version=1、revision 与 rules。
每条修改有独立 ID、operation、anchor、enabled、match、pattern、target、unavailable。
operation 为 prepend / before_final / replace / disable / final；不保存生成后的出口 tag。
目标按所属来源的原始唯一名称解释，随后由现有来源命名空间机制解析。

Clash YAML 规则与原生 JSON route.rules 使用编译器的共享解析投影。修改在源规则降低为
内核规则前应用；新增/替换规则直接生成 JSON。原生未知规则对象完整保留，不反向序列化 YAML。
固定顺序仍是前置动作 → 全局覆盖 → 来源分流 → 模式规则 → 修改后的主规则 → 主默认出口。
次来源不隐式导入内部规则；其个人修改仅在作为主来源时执行。

replace / disable 的 anchor 为带格式前缀的原始规则文本（JSON 使用规范化 DOM 文本），
不以列表索引定位。刷新后原规则必须唯一匹配；缺失、重复、冲突拒绝候选并保留旧内容。
个人修改记录视图仍可撤销有冲突的修改。显示名改名不改变 profile ID；原始对象改名
不自动绑定其它对象。出口失效保留匹配，按明确的 reject / direct / main 策略处理并记保真度；
main 使用原来源默认出口，不重新匹配来源规则，修改默认出口自身不能选 main 回退。

保存检查来源内容与个人修改 revision，拒绝过期表单。活跃主来源走已有候选检查与重启路径；
其它来源独立编译检查。失败恢复原修改，刷新失败不替换原文件。预览无副作用。
Android 继续由后台 libbox 做实际启动校验，未新增完整异步启动失败回滚或跨文件崩溃事务。

不修改 SQLite schema。个人修改写入时确保所属 profile 同事务存在；删除 profile 与对应
修改键同事务提交，settings/profile flush 串行，旧快照写入不能复活已删除修改。
未知持久字段、未知版本拒绝读取；原文中既有手动修改不猜测迁移，保持原样。

## 个人规则集资源库（2026-10-26）

资源库为独立的 `settings["rules.resources"]`，format_version=1、revision、resources
经同一普通 TU 的严格 typed codec 保存，不变更 SQLite schema。资源 ID 与显示名分离，
个人规则 `match="rule_set"` / pattern 保存资源 ID；改名不改变引用。资源库供所有订阅选择，
当前主订阅的启用个人规则、或启用的全局规则引用的集合参与运行；同一集合只加载一次。
全局规则保存相同资源 ID，选择目标来源、组/节点、层级和不可用策略，切主订阅后继续生效。
界面显示资源名称，改名不改变匹配；不会自动应用未引用的资源。

- 远程资源接受 HTTP(S)、JSON source / SRS binary，更新周期为 1–8760 小时。
  编译生成原生 remote rule_set 和显式直连 HTTP client，TLS 保持系统校验；
  下载、运行期定时更新与缓存归 sing-box。保存地址仅校验声明，不表示远端已下载或可用。
- 本地手写内容接受 sing-box 规则集 JSON（version 1–5 + rules），
  单份 8 MiB、内容总计 16 MiB，资源最多 256 个。内容独立保存、编译为 inline headless rules，
  不继续引用原文件，不改文件；逻辑子条件保持原生对象，未知条件由固定内核拒绝。
- 桌面可导入本地 SRS：先有界读取独占快照，再由固定内核 `rule-set decompile` 转为 JSON，
  保存为同一 inline 资源。输入和输出各限 8 MiB，工具限时 15 秒，失败保留表单与原资源；
  不解码未知未来版本，不忽略不能反编译的 AdGuard 二进制条件。只清理本次独占暂存目录。
  Android/iOS 不启动桌面工具，因此继续提供本地 JSON 和远程 SRS。
- 新增/替换的个人规则选择集合、目标与前置/兜底前位置，直接生成原生 rule_set 匹配。
  来源命名空间不改写资源库 ID；与原生订阅已有 tag 冲突拒绝，原有规则集保留。
  远程运行 tag 包含完整 URL/格式身份，修改下载地址不复用旧地址的原生缓存。
- 保存检查资源库 revision，先对全部资源生成独立候选并执行桌面内核检查，成功才写缓存；
  运行时重配失败恢复旧 setting，订阅/规则修改共用生命周期锁。未引用资源也验证声明和本地内容，
  远程内容仍在内核运行时校验。Android 完整校验仍由后台 libbox 执行。
- 删除扫描全部全局规则和现存 profile 的个人规则，包含已禁用记录；仍有引用则拒绝，
  订阅引用给出订阅名称。全局保存入口也检查资源存在，资源编辑和全局写入共用计划生命周期锁。
  删除订阅不删除共享资源；没有后台扫描、资源文件清理或订阅原文重写。

桌面远程资源菜单提供「重新下载（重启内核）」。固定内核没有规则集热更新/状态 RPC，
因此显式增加该资源的 `refresh_generation`，仅轮换它的原生缓存身份，经候选检查后沿现有
重启/恢复流程应用。旧缓存不删除；新下载/启动失败恢复旧资源声明和可恢复的运行计划。
正在运行且被启用规则引用时，只有内核重新就绪才显示「本次已重新下载并应用」；未运行或
未引用则只显示「已安排在下次引用启动时重新下载」。这是本次操作的会话内回执，修改库后清除，
不冒充原生周期更新状态或持久时间戳。手动更新会短暂停止当前内核，Android/iOS 暂不提供此操作。
GEO EOF 自动修复不删除共享 `cache.db`（其中还有个人/订阅资源与选择状态）；计划含非自有
文件资源时，不把无法归属的 EOF 当作 GEO 损坏，也不清理 GEO 文件，避免破坏旧计划的恢复条件。

当前未提供资源推荐目录、原生运行期定时更新时间/下载状态查询、
Clash YAML/text/MRS 导入此资源库，以及订阅原有 provider 的统一资源管理。
这些边界不影响既有 Clash provider 转换路径。修改 JSON 原文的高级入口不受此资源库管理。

运行回归可先用 `test_singbox --personal-rule-fixtures <独立目录>` 生成配置，再执行
`python tests/test_personal_rule_sets_runtime.py <同一目录> <固定 sing-box 路径> <OpenSSL 路径> <test_runtime_health 路径>`。
脚本只启动 loopback HTTP/TLS、SOCKS 与 echo 测试，不访问应用库、不启用 TUN 或系统代理；
最后一个参数调用生产 SRS 导入函数并验证源文件保留、坏输入/超限拒绝与暂存清理，随后验证导入结果的实际匹配。
脚本还覆盖全局引用、新缓存身份强制获取变更内容、同身份复用，以及离线恢复新旧缓存。
省略 OpenSSL 时不覆盖 TLS。`personal_rule_sets_runtime` 已注册到桌面必跑 CTest，使用独占临时目录，
强制传入固定内核、OpenSSL 和两个生产测试程序；缺失/禁用由 `project_test_gate` 拒绝。
手动命令可保留完整配置和日志证据；编译/codec/引用保护断言继续由 singbox / routing 覆盖。
