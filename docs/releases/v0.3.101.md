# Clash-Flux v0.3.101

## 简体中文

- 升级 HuxerUI 到 0.4.0 并迁移工程格式：框架源码/CI pin 为 `144aff6b`（0.4.0 合并线），Android 改为静态链接，框架直接链入 `libclash-flux.so`，不再单独打包 `libhuxerui.so`。
- Android 由 `MainApplication` 在 `Application` 初始化时加载 `BuildConfig.HUXERUI_APP_LIBRARY`，manifest 声明 `android:name=".MainApplication"`；移除 `MainActivity`/`ClashVpnService` 中的重复加载，覆盖 `:background` 进程的服务启动路径。
- Android 改用 `c++_static`，不再随包携带 `libc++_shared.so`；libbox 与其它 JNI 库均不依赖该共享库。
- `huxerui build android --optimization minsize --lto on` 的 Gradle 属性现在会转发为 `HUXERUI_OPTIMIZATION`/`HUXERUI_ENABLE_LTO`；发布构建启用 `minsize` + LTO（CI 通过 Gradle 属性注入）。
- 修复 SDK 模式在 Android/iOS 仍请求 `shared` 组件导致 `find_package(HuxerUI)` 失败的问题，按平台选择 `static`/`shared`。
- 同步扩展库到各自 SDK 0.4.0 迁移提交：Lib-Camera `5d6b8e81`、Lib-SQLite `882665a`、Lib-Charts `a879e96c`、Lib-CodeEditor `a332e7c`、Lib-Media `01341304`；保留 PieChart/PieChartData、紧凑图表高度、SQLite 只读启动查询、Camera Linux 采集与 Media 图片选择等 fork 行为。
- 应用侧跟随扩展重命名：Media 头文件改为 `<huxerui/media_library.h>`；SDK 模式最低要求提升到 HuxerUI 0.4.0。
- Android versionName 为 **0.3.101**，versionCode 为 **179**（上一发布 178）；sing-box/libbox 1.14.4 与其它依赖固定版本不变。
- 体积（本地 arm64-v8a Release）：SDK 0.4.0 + `minsize` + LTO 为 **39,400,763 B（37.57 MiB）**；源码 0.4.0 默认 Release 为 **40,695,859 B（38.81 MiB）**。迁移前同代码的 0.3 shared 默认 Release 为 42,894,702 B（40.91 MiB）。
- 验证：SDK 0.4.0 `minsize`+LTO 与源码 `144aff6b` 默认 Release 均构建通过；APK 仅 `arm64-v8a`，无 `libc++_shared.so`/`libhuxerui.so`，v1/v2 签名通过；桌面源码构建、`./run.sh --version`、`git diff --check` 通过，`ctest -L clashflux-required` 32/32。未做真机安装/启动，发布 APK 由标签 CI 使用正式密钥签名与核验。

## English

- Upgrade HuxerUI to 0.4.0 and migrate the project format: the framework source/CI pin is `144aff6b` (0.4.0 integration line). Android now links the framework statically into `libclash-flux.so`, so no separate `libhuxerui.so` is packaged.
- Android loads `BuildConfig.HUXERUI_APP_LIBRARY` from `MainApplication` during `Application` initialization, with `android:name=".MainApplication"` in the manifest. Duplicate loads in `MainActivity`/`ClashVpnService` are removed, which also covers service startup in the `:background` process.
- Android switches to `c++_static`; the APK no longer carries `libc++_shared.so`. libbox and the other JNI libraries do not depend on it.
- Gradle properties from `huxerui build android --optimization minsize --lto on` are forwarded to `HUXERUI_OPTIMIZATION`/`HUXERUI_ENABLE_LTO`; release builds use `minsize` + LTO (CI injects the properties).
- Fix SDK mode requesting the `shared` component on Android/iOS, which made `find_package(HuxerUI)` fail; the component is now selected per platform.
- Update extension libraries to their SDK 0.4.0 migration commits: Lib-Camera `5d6b8e81`, Lib-SQLite `882665a`, Lib-Charts `a879e96c`, Lib-CodeEditor `a332e7c`, Lib-Media `01341304`. Fork behavior is preserved: PieChart/PieChartData, compact chart height, SQLite read-only startup queries, Camera Linux capture and Media image picking.
- App-side rename follow-up: the Media header is now `<huxerui/media_library.h>`; SDK mode now requires HuxerUI 0.4.0 as the minimum.
- Android versionName is **0.3.101**, with versionCode **179** (previous release 178); sing-box/libbox 1.14.4 and other dependency pins are unchanged.
- Size (local arm64-v8a release): SDK 0.4.0 + `minsize` + LTO is **39,400,763 B (37.57 MiB)**; source 0.4.0 default release is **40,695,859 B (38.81 MiB)**. The pre-migration 0.3 shared default release was 42,894,702 B (40.91 MiB).
- Verification: SDK 0.4.0 `minsize`+LTO and source `144aff6b` default release both build. The APK is `arm64-v8a` only, has no `libc++_shared.so`/`libhuxerui.so`, and passes v1/v2 signature verification. The desktop source build, `./run.sh --version`, `git diff --check` and 32/32 required regressions pass. Real-device install/startup was not tested; tag CI signs and verifies the release APK with the production key.
