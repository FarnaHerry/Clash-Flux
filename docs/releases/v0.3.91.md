# Clash-Flux v0.3.91

## 简体中文

- 首批实现 HTTP `proxy-providers`：下载远程节点并展开到 `select` 组的 `use` / `include-all-providers`，支持 Clash `proxies` 和现有 Base64 VMess 节点订阅格式。
- provider 默认 DIRECT 下载，支持单值请求头、`interval`、`size-limit` 和完整身份验证缓存。手动刷新主订阅会强制更新引用中的 provider；启动时到期刷新失败可沿用已验证缓存并给出警告。
- 节点与规则集缓存统一经过完整候选检查后提交。下载、解析或候选失败保留旧订阅、旧缓存和运行配置，不再把未准备的代理组静默改成 DIRECT。
- 本批仍不支持 file/inline provider、非空筛选或 payload、启用的健康检查、provider-backed url-test、override、age 加密、非 DIRECT 下载及 `include-all`；遇到这些字段会明确拒绝候选。
- 停止或桌面待命状态下，可以删除无其他引用的主订阅，包括唯一主订阅。待命删除会先切换为空的待命配置，成功后才删除记录；失败恢复原选择和配置。活动代理及其他引用保护不变。
- 已验证真实 sing-box 经 provider 节点转发、CLI 刷新回滚及 Android 构建；尚未做 Android 真机外网、VPN 或正式签名覆盖安装验收。
- Android versionCode 为 169。

## English

- Added the first HTTP `proxy-providers` subset: remote nodes are downloaded and expanded into `select` groups through `use` / `include-all-providers`, supporting Clash `proxies` and the existing Base64 VMess subscription format.
- Providers download through DIRECT by default, with single-value headers, `interval`, `size-limit` and fully identity-checked caches. Refreshing a main subscription forces referenced providers to update; an expired-provider failure during startup can reuse a verified cache with a warning.
- Proxy and rule-provider caches are committed only after the complete candidate passes validation. Download, parsing or candidate failures preserve the previous subscription, cache and runtime configuration instead of silently turning an unprepared group into DIRECT.
- This subset does not yet support file/inline providers, non-empty filters or payload, enabled health checks, provider-backed url-test, overrides, age encryption, non-DIRECT downloads or `include-all`; these inputs explicitly reject the candidate.
- A main subscription with no other references can now be removed while stopped or in desktop standby, including the only subscription. Standby deletion first switches to an empty standby configuration and preserves the previous selection and configuration on failure. Active-proxy and other reference protections remain unchanged.
- Real sing-box forwarding through a provider node, CLI refresh rollback and Android builds were verified. Android device Internet access, VPN behavior and signed upgrade installation have not been verified on-device.
- Android versionCode is 169.
