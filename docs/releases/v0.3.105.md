# Clash-Flux v0.3.105

## 简体中文

- 本版本替代未创建 Release 的 `v0.3.102`/`v0.3.103`/`v0.3.104`：`.102` 修复 Windows 测试写入与 gzip 能力假设；`.103` 暴露框架合并的 macOS AppKit 构造错误和 iOS CLI 桩缺失；`.104` 已构建通过但 macOS 测试缺少内核路径，本版补齐。
- 存储分层重构：新增独立 `clashflux.data` DataSession，启动时单独打开、hydrate 和关闭 SQLite；删除 `clashflux.db` 门面与仅转发的 `persistence` 单元。`CoreStore`、订阅、设置和 UI 模型改为直接依赖数据会话与共享 DTO 快照。保留现有 SQLite schema v2、全部订阅来源文件与旧 `id.yaml` 引用，不重建、不清理。
- 订阅提交协议：刷新和原文编辑先独占暂存并完成解析/候选检查，完整同步来源文件与父目录后按来源修订号原子提交；失败保留旧文件、引用和活动配置。每个来源使用单调修订号，拒绝 ABA 与迟到完成；桌面下载提交前核对原文字节，Android 更新沿用抓取前修订。
- 新导入与后台资源准备：导入先保存完整原文并立即发布卡片；应用任务域随后准备 provider/ASN，卡片显示准备中、就绪或失败，右键“准备连接资源”可重试。失败保留来源供查看/编辑；删除或换版本取消旧准备，旧 ticket 不能覆盖新结果。CLI 新增 `profile prepare <id>`，`profile import` 成功只表示文档已保存。
- 候选复用与下载留存：`CoreStore` 保留最多 32 MiB、最长 60 秒的完整已校验编译结果，按 CompileOptions、资源完整身份、设置/来源修订和原始正文核对；手动强制刷新绕过。校验成功的独立下载可写入 `.downloads` 供重试复用，不切换活动 provider 引用。超过 8 MiB 的 Geo/ASN 请求使用 120 秒单次预算；桌面 curl 在构建含 zlib 时协商 gzip（Windows 内置 curl 无 zlib，保持 identity）；Android 使用平台透明 gzip，解压后正文仍受大小上限约束。
- CLI 与无窗启动：数据库命令只启动同一无窗 Runtime，完成命令与落库后退出，不注册托盘或呈现轮询；已有 GUI 实例的命令仍走单实例 IPC。Linux 资源回归新增预创建窗口失败 guard，避免真实 CLI 测试闪窗或抢焦点。
- UI：设置首页在配置 hydrate 前保留静态 `—` 行，不展示默认值或允许写入，就绪后原位启用。滚动条使用 16pt 对称槽位，滑块避开 Linux 6pt 窗口拉伸带；鼠标悬停正文或滚动条槽即以主题主色高亮，离开取消、拖动保持，嵌套时只选最深且实际有溢出的 hover 容器，滚动方向与偏移不再参与选择。
- 框架与依赖：HuxerUI 固定 `e720ae5f`（在 `cd66ef31` 上修复 macOS `AppKitPlatformViews` 构造参数与 `unique_ptr<AppKitRenderer>` 的合并错误；`cd66ef31` 合入官方 `ad28dd34`，平台段落布局测量/绘制复用；核心 API 与 Linux Pango 路径不变）；curl 8.23.0、glaze 9.1.0、IXWebSocket 12.1.0、yaml-cpp 0.9.0；Lib-Charts `2251bab5`、Lib-Media `fbe5b7e6`。sing-box/libbox 1.14.4 不变。
- Android versionName 为 **0.3.105**，versionCode 为 **183**（v0.3.102/103/104 未发布）。订阅下载改用平台透明 gzip，不再强制 `Accept-Encoding: identity`；解压后的正文长度仍按 maxBytes 检查。
- iOS 构建修复：桌面伪 CLI 入口在 iOS 上也收束为空实现，`RunPendingCliCommand` 不再未声明；iOS 仍是 advisory Simulator 编译，不生成 IPA。
- macOS 测试修复：CI test 构建没有把 `engines/sing-box` 放到测试二进制旁，`core_api_lifetime` 的准备检查因此在 macOS 上 spawn 失败；测试在 POSIX 的临时目录生成可执行 `sing-box` stub 并加入 PATH，仅在找不到真实内核时生效。产品路径未变。
- Windows 回归修复：`test_persistence`/`test_core_api_lifetime` 的源文件写入改为二进制模式，避免 Windows 文本模式重复转换 CRLF；`rule_provider_download` 的 gzip 断言按 libcurl 是否带 zlib 选择压缩或 identity，Windows 不再强制要求 gzip。产品下载路径未变。
- 验证：`cmake --build build --target clash-flux test_page_transition`、`./run.sh --version`（v0.3.105）、`git diff --check` 通过；`ctest --test-dir build --output-on-failure -L clashflux-required` **32/32**（175.55 秒），含 page_transition 与 ui_resources；`./build/test_page_transition --scrollbars` 专项通过；Android `:app:externalNativeBuildDebug :app:compileDebugJavaWithJavac` 通过。macOS/iOS 平台构建由标签 CI 复验；本机未构建。未做真机安装/启动与正式签名；发布 APK 由标签 CI 使用正式密钥签名并核验。

## English

- This release supersedes the unreleased `v0.3.102`/`v0.3.103`/`v0.3.104`: `.102` fixed Windows test file-write modes and a gzip capability assumption; `.103` exposed a framework-merge AppKit construction error and a missing iOS CLI stub; `.104` built but its macOS test lacked a core binary path. This version completes it.
- Storage layering: a new independent `clashflux.data` DataSession opens, hydrates and closes SQLite on its own. The `clashflux.db` facade and the forwarding-only `persistence` unit are removed; `CoreStore`, profiles, settings and UI models now depend directly on the data session and shared DTO snapshots. SQLite schema v2, every profile source file and legacy `id.yaml` references are preserved without rebuild or cleanup.
- Profile commit protocol: refresh and raw editing stage exclusively and finish parsing/candidate checks before atomically committing file plus metadata under the source revision. Failures retain the old file, references and active configuration. Monotonic per-source revisions reject ABA and late completions; desktop downloads verify the original bytes before commit, and Android updates carry the pre-fetch revision.
- Import and background resource preparation: an import first stores the complete document and publishes the card; an application-scope task then prepares provider/ASN resources with preparing/ready/failed status and a "Prepare connection resources" retry. Failures keep the source; deleting or replacing it cancels old work, and stale tickets cannot overwrite newer results. The CLI adds `profile prepare <id>`; a successful `profile import` only confirms document storage.
- Candidate reuse and download retention: `CoreStore` keeps a complete validated compilation result for at most 32 MiB and 60 seconds, keyed by CompileOptions, full resource identity, settings/source revisions and raw text; forced refresh bypasses it. Validated standalone downloads may be retained under `.downloads` for retries without switching provider references. Geo/ASN requests above 8 MiB use a single 120-second budget; desktop curl negotiates gzip when built with zlib (the Windows vendored curl has no zlib and keeps identity); Android uses transparent gzip, and decoded bodies still obey the size limit.
- CLI and windowless startup: database commands start the same windowless Runtime, finish the command and persistence, then exit without tray or presentation polling; commands against an existing GUI instance still use single-instance IPC. The Linux resource regression adds a pre-window-creation failure guard to avoid flashing or focus stealing.
- UI: the settings home keeps static `—` rows until configuration hydration instead of presenting defaults or accepting writes, then enables controls in place. Scrollbars use 16pt symmetric gutters and clear the Linux 6pt resize band. Hovering scrollable content or the scrollbar gutter highlights the thumb in the theme primary color; leaving clears it, dragging keeps it, and nested areas select only the deepest hovered container with real overflow. Scroll direction and offset no longer participate in selection.
- Framework and dependencies: HuxerUI is pinned to `e720ae5f` (fixes the macOS `AppKitPlatformViews`/`unique_ptr<AppKitRenderer>` merge error on top of `cd66ef31`; `cd66ef31` merges upstream `ad28dd34`, reusing platform paragraph layouts for measurement and drawing; core API and the Linux Pango path are unchanged). curl 8.23.0, glaze 9.1.0, IXWebSocket 12.1.0 and yaml-cpp 0.9.0 are updated; Lib-Charts is `2251bab5` and Lib-Media `fbe5b7e6`. sing-box/libbox 1.14.4 is unchanged.
- Android versionName is **0.3.105** and versionCode is **183** (`v0.3.102`/`v0.3.103`/`v0.3.104` were not released). Subscription downloads use platform-transparent gzip instead of forcing `Accept-Encoding: identity`; decoded bodies remain bounded by maxBytes.
- iOS build fix: the desktop pseudo-CLI entry points are stubbed on iOS as well, so `RunPendingCliCommand` is declared. iOS remains an advisory Simulator build and produces no IPA.
- macOS test fix: CI test builds do not place `engines/sing-box` next to the test binary, so the `core_api_lifetime` preparation check failed to spawn it on macOS. The test now creates an executable `sing-box` stub in its POSIX temp directory and prepends it to PATH; the real engine still wins when present. Product paths are unchanged.
- Windows regression fixes: `test_persistence` and `test_core_api_lifetime` now write source files in binary mode so Windows text translation cannot double CRLF; `rule_provider_download` selects compressed or identity assertions from libcurl zlib capability, so Windows no longer requires gzip. The product download path is unchanged.
- Verification: `cmake --build build --target clash-flux test_page_transition`, `./run.sh --version` (v0.3.105) and `git diff --check` pass. `ctest --test-dir build --output-on-failure -L clashflux-required` is **32/32** (175.55 s), including page_transition and ui_resources; the dedicated `--scrollbars` run passes; Android `:app:externalNativeBuildDebug :app:compileDebugJavaWithJavac` passes. macOS/iOS platform builds are revalidated by tag CI; this host did not build them. Real-device install/startup and production signing were not exercised locally; tag CI signs and verifies the release APK with the production key.
