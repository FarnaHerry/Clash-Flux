# Clash-Flux v0.3.96

## 简体中文

- 网站测试支持编辑与删除：初始八项与新增站点共用同一套模型、表单和操作菜单，可改地址/备注或确认删除，删空后显示空状态并保留添加入口。添加/编辑共用 MD3 平铺表单：宽屏弹窗、Compact 独立二级页（返回箭头/系统返回），字段为「网站地址」和「备注（可选）」；备注留空时用主机名作标题。裸域名自动补 `https://`，协议与主机名规范化后去重，保留路径/查询大小写；拒绝非 HTTP(S)、用户信息、片段、无效端口、重复 URL 和超过 2048 字符的输入，最多 24 项。取消、Esc、遮罩和返回共用草稿放弃确认，失败用 toast 反馈并保留输入。
- 网站测试改为单卡独立排队与取消：单卡测试不再阻塞或取消其它卡的请求，全局仍最多 3 个并发、超出按发起顺序暂存；页头「取消」结束全部在途与暂存任务。结果按稳定站点 ID 和请求代次核对后发布，删除、取消或列表索引移动不会让旧结果覆盖新请求；修改地址会取消该站点的请求并重置结果，仅改备注保留结果与在途请求。
- Android 应用内更新拆分职责：下载与 APK 校验保留在应用作用域 `AppUpdateModule` / `AndroidAppUpdateVerifier`，授权与安装迁移到窗口作用域 `AppUpdatePresentationModule` / `AndroidAppUpdatePresentation`，通过 HUI `JavaWindowPlatformModuleFactory` 注册并只在创建时捕获原窗口的 Activity Result launcher。移除 MainActivity 的更新专用静态查找、请求码和手写结果槽；Intent 与文件选择器共用呈现队列和结果路由。窗口关闭时显式关闭模块，`AwaitCallback` 配合待完成账本结束仍存活的安装等待，失败路径恢复同一持久化会话并保留 APK 供重试。
- Camera 依赖追新：Lib-Camera 固定 `d51a2f09`，新增 Linux V4L2 预览/拍照、X11 与 ScreenCast/PipeWire 屏幕选区（`CaptureSource::Screen` / `ScreenPreview`）、`CapturePreviewFrameAsync`；Android Camera 模块改用窗口级工厂并绑定原 `HuxerUIView`，iOS 改用 `WindowPlatformModuleFactory`，拍照等待由工作线程改为 `AwaitCallback`。框架固定 `a755f9ff`，该提交为扩展暴露 Win32 HWND 与 Linux GTK 原生 surface/aperture。应用页面仍只使用既有相机接口，Linux 扫码由「不可用」变为可用的 V4L2 路径。
- 修复 Android 增量构建可能继续编译旧页面副本的问题：`AndroidLegacy.cmake` 把共享 UI 源文件加入 configure 依赖，页面改动后 Gradle 构建会重新生成镜像。
- HuxerUI 固定 `a755f9ff`（SDK 0.4.0），Lib-Camera 固定 `d51a2f09`，Lib-SQLite/Lib-Charts/Lib-CodeEditor 固定提交不变；sing-box/libbox 保持 1.14.4。Android versionName 为 0.3.96，versionCode 为 174。
- 验证：本地桌面全目标构建及 31/31 必跑回归通过，覆盖网站测试分页与表单、应用升级等待账本、持久化、DNS/TLS、Provider、资源管理与运行控制；Android Debug Java/NDK 构建与 `testAppUpdatePolicy` 等宿主策略通过。正式多平台安装包与 APK 签名由标签 CI 核验。
- 边界：网站测试只验证 HTTP 响应，不代表完整网页加载，也不代表其它应用的 VPN/TUN 分流；真实摄像头预览/拍照、屏幕选区、Android 真机授权与安装、Compact 二级页真实键盘/系统返回未在本地验收。跨平台安装与设备行为以实际产物和实机结果为准。

## English

- Website Tests now supports editing and deleting sites. The eight defaults and any added sites share one model, form and action menu; addresses and notes can be changed and deletions require confirmation. An empty list shows an empty state and keeps the add entry. The shared MD3 flat form opens as a wide dialog or a compact sub-page (back arrow/system back) with "Website address" and optional "Note" fields; an empty note falls back to the host name. Bare hosts gain `https://`, protocol and host are normalized before duplicate detection while path/query case is preserved. Non-HTTP(S) input, user info, fragments, invalid ports, duplicate URLs and values over 2048 characters are rejected; the list holds at most 24 entries. Cancel, Esc, scrim and back share the draft-discard confirmation, and failures keep the input.
- Website Tests now queue and cancel per card. Testing one card no longer blocks or cancels other cards, while the global limit stays at three concurrent requests with FIFO overflow; the header Cancel ends all running and queued requests. Results are published against stable site IDs and request generations, so deletion, cancellation or list reordering cannot overwrite newer requests. Changing an address cancels that site's request and resets its result; changing only the note preserves both.
- Android in-app updates now split responsibilities: download and APK verification stay in the application-scoped `AppUpdateModule` / `AndroidAppUpdateVerifier`, while authorization and installation move to the window-scoped `AppUpdatePresentationModule` / `AndroidAppUpdatePresentation`, registered through the HUI `JavaWindowPlatformModuleFactory` and capturing the original window's Activity Result launcher at creation. The MainActivity update-specific static lookup, request codes and hand-written result slot are removed; intents share the presentation queue and result routing with the file picker. Window teardown closes the module, and `AwaitCallback` plus a pending-call ledger settle surviving install waits. Failure paths restore the same persisted session and keep the APK for retry.
- Camera dependencies updated: Lib-Camera is pinned to `d51a2f09`, adding Linux V4L2 preview/photo capture, X11 and ScreenCast/PipeWire screen-region capture (`CaptureSource::Screen` / `ScreenPreview`) and `CapturePreviewFrameAsync`. The Android module now uses the window-scoped factory bound to the original `HuxerUIView`, iOS uses `WindowPlatformModuleFactory`, and photo waits moved from worker threads to `AwaitCallback`. HuxerUI is pinned to `a755f9ff`, which exposes Win32 HWND and Linux GTK native surfaces/apertures to extensions. Application pages keep using the existing camera APIs; Linux QR scanning moves from Unavailable to the V4L2 path.
- Fixed stale page copies in incremental Android builds: `AndroidLegacy.cmake` adds the shared UI sources to configure dependencies so Gradle regenerates the mirror after page edits.
- HuxerUI is pinned to `a755f9ff` (SDK 0.4.0) and Lib-Camera to `d51a2f09`; Lib-SQLite/Lib-Charts/Lib-CodeEditor pins are unchanged, and sing-box/libbox remains 1.14.4. Android versionName is 0.3.96 and versionCode is 174.
- Validation: the local full desktop build and all 31 required regressions passed, covering Website Tests pagination/forms, the app-update wait ledger, persistence, DNS/TLS, Providers, resource management and runtime control. Android Debug Java/NDK and host policy tests including `testAppUpdatePolicy` passed. Tag CI verifies release packages and the APK signature.
- Boundaries: Website Tests only verify an HTTP response, not a fully loaded page or other applications' VPN/TUN routing. Real camera preview/photo capture, screen-region capture, Android device authorization/installation and the compact sub-page's real keyboard/system back were not validated locally. Cross-platform installation and device behaviour depend on the actual artifacts and hardware checks.
