# Clash-Flux v0.3.88

## 简体中文

- 修复 Android 重启、sticky 恢复或重配后 sing-box 可能从 `cache.db` 恢复旧 `direct`，而应用仍按保存的 `rule` 显示，导致流量全部直连的问题。
- Android 后台通过 libbox CommandClient 读取初始实际模式，必要时切换到配置目标，并等待更新回调确认；验证失败不再提前发布 Running。
- Starting 阶段修改模式会更新本次启动目标并重新协调；无 TUN 常驻内核也支持运行中热切换。
- 实际模式经现有 Binder/JNI 快照回传到界面，不新增第二份持久化状态；运行中不再以保存意图掩盖内核实际模式。
- 新增 Android JVM 模式协调回归，覆盖缓存 `direct` 模拟恢复、异步确认、启动期间目标变化、未确认失败及控制通道重置，并同步踩坑文档。
- Android versionCode 为 166；桌面代理行为不变。

## English

- Fixed an Android issue where sing-box could restore an old `direct` mode from `cache.db` after restart, sticky recovery or reconfiguration while the app still showed the saved `rule`, silently sending all traffic through the direct outbound.
- The Android runtime now reads the actual initial mode through the libbox CommandClient, changes it to the configured target when needed, and waits for the update callback before publishing Running; verification failure no longer reports a ready runtime.
- Mode changes during Starting now replace the startup target and trigger another reconciliation. The resident no-TUN core also supports live mode switching.
- The actual mode is returned to the UI through the existing Binder/JNI snapshot without adding another persisted source of truth, so the running UI no longer masks the runtime mode with the saved intent.
- Added Android JVM reconciliation regressions for simulated cached `direct` recovery, asynchronous confirmation, target changes during startup, missing confirmation and control-channel resets, and updated the troubleshooting documentation.
- Android versionCode is 166; desktop proxy behavior is unchanged.
