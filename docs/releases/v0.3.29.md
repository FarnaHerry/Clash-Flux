# Clash-Flux v0.3.29

## 简体中文

- 修复规则页的大列表卡顿，缓存规则筛选索引并减少深层布局重复测量；升级固定 HuxerUI 集成版本。
- 每个配置新增独立、只读的保真度页面，完整展示转换记录与错误。
- 应用与内核日志统一为一个按时间排列的列表，共享搜索、筛选、导出和清空。
- 首页新增内网 IP 与网络检测卡片，支持重新检测公网代理出口；更新系统代理与 TUN 图标。
- 调整内容留白与胶囊导航主题、选中动画，改进窄窗口的订阅搜索和导入入口。

- Windows 改用原生 SCM 服务 `ClashFluxService`：由 LocalSystem 服务托管 sing-box、PPTP/RAS 与 TUN 路由补偿，应用保持普通用户权限，数据库与订阅仍由应用管理。
- 设置页新增 Windows 服务安装、更新和卸载。UAC 只提升服务管理子命令；开启 TUN 不再重启为管理员 GUI。首次使用需安装服务，升级应用后需同步更新服务版本。
- 服务控制与只读查询使用受限的独立命名管道，验证安装用户 SID 和 SCM 进程身份。PPTP 长时间拨号不会阻塞内核状态查询；服务载荷位于受保护的 Program Files 独立目录。
- 使用 Job Object 清理服务持有的内核进程；正常停止时先释放路由补偿与 VPN 会话。取消 UAC 会保留当前代理运行状态，CLI 状态查询不会误停止后台内核。
- 新增 Windows SCM 生命周期回归与跨平台协议回归，并纳入桌面发布门禁。CI 验证使用隔离服务及假内核，不替代真实 TUN/PPTP 流量验收。

Windows 部署和生命周期说明见 [Windows 服务](https://github.com/FarnaHerry/Clash-Flux/blob/v0.3.29/docs/windows-service.md)。正常退出应用仍会停止内核；关闭到托盘时继续运行。

## English

- Reduce large rules-page stalls with cached filter indices and fewer repeated deep-layout measurements, using an updated pinned HuxerUI integration.
- Each configuration gains a dedicated read-only fidelity page with the complete conversion report and errors.
- Application and core logs share one chronological list with unified search, filters, export and clearing.
- The home page adds LAN IP and network-check cards, including manual proxy-egress checks; system proxy and TUN icons are refreshed.
- Refine page spacing and capsule navigation colors/selection motion, and improve compact subscription search and import actions.

- Windows now uses the native SCM `ClashFluxService`. The LocalSystem service owns sing-box, PPTP/RAS and TUN route compensation; the application remains unelevated and retains ownership of its database and subscription data.
- Settings adds service installation, updates and removal. UAC elevates only the service-management command; enabling TUN no longer relaunches the GUI as administrator. Install the service before first use and update it after upgrading the application.
- Restricted, separate control and query pipes authenticate the installation user SID and the SCM process. Long PPTP dialing operations no longer block core-status queries. Service binaries reside in a protected Program Files directory.
- A Job Object cleans up the service-owned core. Normal shutdown releases route compensation and VPN sessions first. Cancelling UAC preserves the running proxy, and a status-only CLI client does not stop the background core when it exits.
- Native Windows SCM lifecycle tests and cross-platform protocol tests are required desktop release gates. CI uses an isolated service and a fake core; it does not replace real TUN/PPTP traffic validation.

See [Windows service deployment](https://github.com/FarnaHerry/Clash-Flux/blob/v0.3.29/docs/windows-service.md). Exiting the application still stops the core; hiding it to the tray keeps it running.
