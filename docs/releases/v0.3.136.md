## 中文

- 修复 VMess 明文 TCP（`net="tcp"` 且 `type=""` / `"none"`，含 `net="tls"`）订阅节点因携带未使用的 `path` 字段而报错失败的问题：忽略该未使用的传输路径并按近似转换记录保真度说明，`type="http"` 等非空伪装传输继续严格拒绝；同步更新节点订阅与保真度文档。
- 新增应用级领域线程池 `DomainWorkerPool`（及支持 `std::stop_token` 协同取消的 `RunOnTaskThreadWithStop`），将外部资源 30 秒定时刷新泵从 HuxerUI `WorkerSequence` 迁出，彻底隔离阻塞式领域任务与 HuxerUI SQLite 异步线程池，解决桌面端刷新订阅时因共用线程池饥饿导致的无限转圈死锁。
- 新增基于单线程 `curl_multi` 的非阻塞异步传输引擎（`CurlMultiEngine`），将桌面端订阅刷新/远程导入/30 秒自动更新（落库改为直接 `co_await commitProfile`，消除 `future.get()`）、单节点/策略组延迟测速、首页公网出口 IP 检测与内置 `.srs` 规则集启动预取升级为非阻塞协程或单线程并发传输；同步修复规则页个人规则集刷新的协程栈变量按引用捕获隐患。
- Android versionName 为 0.3.136，versionCode 为 213。

## English

- Fixed VMess plain TCP (`net="tcp"` with `type=""` / `"none"`, including `net="tls"`) subscription nodes failing on unused `path` values: ignore the unused transport path while recording an approximate fidelity note, and keep strictly rejecting spoofed non-empty types such as `type="http"`, with updated node subscription and fidelity documentation.
- Isolated blocking domain work from HuxerUI's SQLite async worker pool via an application-owned `DomainWorkerPool` (including cooperative `std::stop_token` support in `RunOnTaskThreadWithStop`) and moved the 30s external-resource refresh pump off HuxerUI `WorkerSequence`, resolving the desktop subscription refresh spinner deadlock.
- Upgraded desktop subscription refresh/remote import/30s auto-refresh (using direct `co_await commitProfile` instead of synchronous `future.get()`), node/group delay tests, desktop home public-IP probes, and startup built-in `.srs` rule-set prefetch to a single-thread non-blocking `curl_multi` async engine (`CurlMultiEngine`) bridged to HuxerUI coroutines, and fixed a dangling coroutine-stack reference capture in personal rule-set refresh.
- Android versionName is 0.3.136 and versionCode is 213.
