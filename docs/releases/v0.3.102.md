# Clash-Flux v0.3.102

## 简体中文

- 存储分层重构：新增独立 `clashflux.data` DataSession，启动时单独打开、hydrate 和关闭 SQLite；删除 `clashflux.db` 门面与仅转发的 `persistence` 单元。`CoreStore`、订阅、设置和 UI 模型改为直接依赖数据会话与共享 DTO 快照。保留现有 SQLite schema v2、全部订阅来源文件与旧 `id.yaml` 引用，不重建、不清理。
- 订阅提交协议：刷新和原文编辑先独占暂存并完成解析/候选检查，完整同步来源文件与父目录后按来源修订号原子提交；失败保留旧文件、引用和活动配置。每个来源使用单调修订号，拒绝 ABA 与迟到完成；桌面下载提交前核对原文字节，Android 更新沿用抓取前修订。
- 新导入与后台资源准备：导入先保存完整原文并立即发布卡片；应用任务域随后准备 provider/ASN，卡片显示准备中、就绪或失败，右键“准备连接资源”可重试。失败保留来源供查看/编辑；删除或换版本取消旧准备，旧 ticket 不能覆盖新结果。CLI 新增 `profile prepare <id>`，`profile import` 成功只表示文档已保存。
- 候选复用与下载留存：`CoreStore` 保留最多 32 MiB、最长 60 秒的完整已校验编译结果，按 CompileOptions、资源完整身份、设置/来源修订和原始正文核对；手动强制刷新绕过。校验成功的独立下载可写入 `.downloads` 供重试复用，不切换活动 provider 引用。超过 8 MiB 的 Geo/ASN 请求使用 120 秒单次预算；桌面 curl 与 Android 使用平台透明 gzip，解压后正文仍受大小上限约束。
- CLI 与无窗启动：数据库命令只启动同一无窗 Runtime，完成命令与落库后退出，不注册托盘或呈现轮询；已有 GUI 实例的命令仍走单实例 IPC。Linux 资源回归新增预创建窗口失败 guard，避免真实 CLI 测试闪窗或抢焦点。
- UI：设置首页在配置 hydrate 前保留静态 `—` 行，不展示默认值或允许写入，就绪后原位启用。滚动条使用 16pt 对称槽位，滑块避开 Linux 6pt 窗口拉伸带；鼠标悬停正文或滚动条槽即以主题主色高亮，离开取消、拖动保持，嵌套时只选最深且实际有溢出的 hover 容器，滚动方向与偏移不再参与选择。
- 框架与依赖：HuxerUI 固定 `cd66ef31`（合入官方 `ad28dd34`，平台段落布局测量/绘制复用；核心 API 与 Linux Pango 路径不变）；curl 8.23.0、glaze 9.1.0、IXWebSocket 12.1.0、yaml-cpp 0.9.0；Lib-Charts `2251bab5`、Lib-Media `fbe5b7e6`。sing-box/libbox 1.14.4 不变。
- Android versionName 为 **0.3.102**，versionCode 为 **180**（上一发布 179）。订阅下载改用平台透明 gzip，不再强制 `Accept-Encoding: identity`；解压后的正文长度仍按 maxBytes 检查。
- 验证：`cmake --build build --target clash-flux test_page_transition`、`./run.sh --version`（v0.3.102）、`git diff --check` 通过；`ctest --test-dir build --output-on-failure -L clashflux-required` **32/32**（179.75 秒），含 page_transition 与 ui_resources；`./build/test_page_transition --scrollbars` 专项通过；Android `:app:externalNativeBuildDebug :app:compileDebugJavaWithJavac` 通过。未做真机安装/启动与正式签名；发布 APK 由标签 CI 使用正式密钥签名并核验。

## English

- Storage layering: a new independent `clashflux.data` DataSession opens, hydrates and closes SQLite on its own. The `clashflux.db` facade and the forwarding-only `persistence` unit are removed; `CoreStore`, profiles, settings and UI models now depend directly on the data session and shared DTO snapshots. SQLite schema v2, every profile source file and legacy `id.yaml` references are preserved without rebuild or cleanup.
- Profile commit protocol: refresh and raw editing stage exclusively and finish parsing/candidate checks before atomically committing file plus metadata under the source revision. Failures retain the old file, references and active configuration. Monotonic per-source revisions reject ABA and late completions; desktop downloads verify the original bytes before commit, and Android updates carry the pre-fetch revision.
- Import and background resource preparation: an import first stores the complete document and publishes the card; an application-scope task then prepares provider/ASN resources with preparing/ready/failed status and a "Prepare connection resources" retry. Failures keep the source; deleting or replacing it cancels old work, and stale tickets cannot overwrite newer results. The CLI adds `profile prepare <id>`; a successful `profile import` only confirms document storage.
- Candidate reuse and download retention: `CoreStore` keeps a complete validated compilation result for at most 32 MiB and 60 seconds, keyed by CompileOptions, full resource identity, settings/source revisions and raw text; forced refresh bypasses it. Validated standalone downloads may be retained under `.downloads` for retries without switching provider references. Geo/ASN requests above 8 MiB use a single 120-second budget; desktop curl and Android use transparent gzip while decoded bodies still obey the size limit.
- CLI and windowless startup: database commands start the same windowless Runtime, finish the command and persistence, then exit without tray or presentation polling; commands against an existing GUI instance still use single-instance IPC. The Linux resource regression adds a pre-window-creation failure guard to avoid flashing or focus stealing.
- UI: the settings home keeps static `—` rows until configuration hydration instead of presenting defaults or accepting writes, then enables controls in place. Scrollbars use 16pt symmetric gutters and clear the Linux 6pt resize band. Hovering scrollable content or the scrollbar gutter highlights the thumb in the theme primary color; leaving clears it, dragging keeps it, and nested areas select only the deepest hovered container with real overflow. Scroll direction and offset no longer participate in selection.
- Framework and dependencies: HuxerUI is pinned to `cd66ef31` (merges upstream `ad28dd34`, reusing platform paragraph layouts for measurement and drawing; core API and the Linux Pango path are unchanged). curl 8.23.0, glaze 9.1.0, IXWebSocket 12.1.0 and yaml-cpp 0.9.0 are updated; Lib-Charts is `2251bab5` and Lib-Media `fbe5b7e6`. sing-box/libbox 1.14.4 is unchanged.
- Android versionName is **0.3.102** and versionCode is **180** (previous release 179). Subscription downloads use platform-transparent gzip instead of forcing `Accept-Encoding: identity`; decoded bodies remain bounded by maxBytes.
- Verification: `cmake --build build --target clash-flux test_page_transition`, `./run.sh --version` (v0.3.102) and `git diff --check` pass. `ctest --test-dir build --output-on-failure -L clashflux-required` is **32/32** (179.75 s), including page_transition and ui_resources; the dedicated `--scrollbars` run passes; Android `:app:externalNativeBuildDebug :app:compileDebugJavaWithJavac` passes. Real-device install/startup and production signing were not exercised locally; tag CI signs and verifies the release APK with the production key.
