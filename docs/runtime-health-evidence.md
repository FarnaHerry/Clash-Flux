# 运行健康：系统证据、现场记录与导出

2026-10-25；本轮覆盖独立系统查询、生命周期回归和本地脱敏记录。
入口仍是 **设置 → 运行诊断**。点击“开始诊断”后，可复制或“保存脱敏报告”。
填写 HTTP(S) 目标才会额外发起业务请求；不会根据零流量自动换节点、重启内核或重设网络。

## 查询的含义

报告 v3 同时保留原生控制、兼容接口、有效统计帧、PPTP 三态证据，并增加：

| 字段 | 实际检查 | 限制 |
|---|---|---|
| `os-tun-interface` | 按已接受计划的接口和 IPv4 地址查询操作系统，核对接口 up 和地址匹配 | 不把保存的开关或配置文本当成实际网卡；IPv6 全链路未覆盖 |
| `tun-plan-os-consistency` | 对照运行计划与网卡证据，已停止的旧接口也可查询 | 缺少证据时为 unknown，不自动修复 |
| `os-route-sample` | 查询到文档保留地址 `192.0.2.1` 的系统选路，不向它发包 | 仅为路由表样本，不能代表每条策略、每个目标或带 mark 的连接 |
| `system-proxy-manual` | Windows 当前用户 WinINet 手动代理是否指向实际混合端口 | 不输出代理地址，不宣称覆盖 PAC/WPAD 或所有应用 |
| `tun-dns-route` | 已接受 TUN 的 DNS 地址在操作系统中是否走该 TUN | 自定义/不支持/无法确认的配置保留 unknown/not-checked |
| `tun-dns-roundtrip` | 仅主动诊断时，绑定匹配 TUN 地址和接口，向其 DNS 地址发送一次保留 `.invalid` 名称的 UDP 查询 | 校验来源、ID、问题、响应结构和错误码；NXDOMAIN 只证明 DNS 路径应答，不代表公网正常 |
| `pptp-transport-os-route` | 查询当前 PPTP 服务器的数值地址是否绕过主 TUN，只输出计数 | 不能确认时为 unknown；不输出服务器地址或会话名称 |

DNS 未确认走匹配 TUN 时不发探测包，不回落到物理 DNS。诊断可取消，DNS 等待上限
1.2 秒并使用整体剩余预算。普通后台采样只查询系统，**不发送 DNS 或公网探测请求**。
业务目标仍经当前 mixed 入站，独立列出结果，不能冒充该目标的 TUN 全链路验收。

Windows 使用 IP Helper/注册表读取，不启动 shell、不要求 GUI 提权、不修改网卡、路由或代理。
Linux 提供 getifaddrs/netlink 查询及绑定接口的 DNS 路径；macOS 仅提供接口读取，
选路/DNS 主动检查和手动代理读取暂不支持。Android 的历史沿用 Binder/status 快照，
不从 UI 进程接管后台 VPN；其独立 OS 查询暂不支持。iOS 继续暂缓。
本机验证范围是 Windows；其它平台实现不等于实机验收通过。

2026-10-25 补充（`a826169` 后的工作区）：Linux PPTP 服务已接入三态证据和真实
传输地址回传，沿用与 Windows 相同的历史记录/脱敏选路计数；未知不触发自动清理。
Linux 子进程、接口及共享回滚边界采用隔离回归验证，尚无本批真实 PPTP 服务器验收。

默认 DNS 地址按固定 sing-box 1.14 的 TUN 语义，从首个 IPv4 地址推导下一地址；
显式 `dns_address` 则使用配置值，禁用 DNS 模式不主动探测。
依据：[sing-box TUN](https://sing-box.sagernet.org/configuration/inbound/tun/)、
[GetBestRoute2](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-getbestroute2)、
[IP_UNICAST_IF](https://learn.microsoft.com/en-us/windows/win32/winsock/ipproto-ip-socket-options)。

## 本地现场记录

应用状态任务约每秒检查状态，普通快照最多每 5 秒记一条；系统查询复用约 15 拍的慢采样。
启动、停止及失败也经过同一记录入口。新观测经运行 epoch/state/revision 核对后才发布，
缓存的 OS 结果带年龄且不能跨运行模式或实例复用。

`core/health-history.txt` 只存结构化数值，最多 128 条近期快照和 64 条状态变化记录；
变化记录保留前后两侧证据，避免被正常周期样本全部挤掉。磁盘上限 128 KiB，原子替换，
写盘失败保留内存待写并标记失败，下一次重试；应用重开后读取有界旧记录。
不写数据库，不包含订阅原文、节点/订阅名称、IP、域名、URL、凭据或内核原始日志。
重开读取也只接受规定格式的数字/枚举，不把外部插入文本带入导出。

诊断报告附带最近 32 条快照及保留的状态变化，可直接保存文本。导出由应用任务持有
不可变报告和独占临时目录，关闭诊断弹窗不会让准备结果绑定到已卸载页面；完成或异常后
释放临时文件、恢复保存按钮。没有自动上传。

## 自动回归边界

- `runtime_evidence`：真实 loopback 网卡/选路和绑定 UDP 请求；错误 ID、问题、坏结构、
  DNS 服务器错误、NXDOMAIN、超时、取消；后台/缺失接口不发 DNS；历史容量、重开、
  初始存储失败、提交失败后的重试、脱敏以及多个导出文件的独占清理。
- `singbox`：生产编译器串联生产就绪/停止发布边界，覆盖保存 TUN 意图启动、PPTP
  连接/保留/断开计划、规则刷新、坏候选保留、停止及重启代次、代理模式恢复。
  这里的原生会话是编排输入，不是真实 RAS 拨号。
- `page_transition`：生产诊断 UI 的中英文/默认资源挂载、深浅主题禁用标签绘制对比度、
  窄屏按钮换行、空报告/长报告、保存能力/保存中状态，以及开始、取消、复制、保存交互。
- 服务进程/Job Object、真实内核统计故障及配置热更新仍由原有独立回归覆盖。

这些回归拆开验证编译、发布、服务和系统查询边界。真实服务器、完整系统 TUN/DNS、
跨平台休眠恢复和长时间日常使用仍需单独验收，不把 loopback 测试写成公网或 PPTP 业务成功。
