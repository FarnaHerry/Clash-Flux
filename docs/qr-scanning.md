# Android 二维码扫描与相册选图

## 桌面图标快捷操作

支持 App Shortcuts 的 Android 桌面可长按 Clash-Flux 图标。电源图标「开关」在上，
按当前 VPN 状态请求启动或关闭，首次开启走系统授权。二维码图标「扫一扫」直接打开扫码页。
快捷操作由系统显示，从 Android 7.1 起可用，实际显示取决于桌面启动器。
冷启动等待订阅数据就绪，运行中通过同一个 Activity 打开。扫码或相册识别成功后进入
配置确认页，用户点击导入后才保存。返回回到原页面，重复触发时保留已经打开的扫码流程。
静态快捷操作先进入独立任务中的透明中转 Activity，再以固定动作转发给 MainActivity，
避免 Android 静态快捷操作的清任务标志销毁正在使用的窗口或表单。开关快捷方式在
1.5 秒窗口内通过后台控制 Binder 读取实时 `vpnState`，不再只依赖开机恢复快照；
读取失败才退回最近持久状态。授权页带 `NEW_TASK`，不会因再次触发快捷方式被中转任务清掉。

iOS 的 Home Screen Quick Actions 需要框架宿主转发冷启动与热启动回调，并接入 iOS 扫码页。
详见 [iOS 构建范围](ios-build.md#当前构建范围)。

## 使用与生命周期

Android 配置导入的扫码页在页头提供「从相册选择」图标，打开系统图片选择器，
每次选择一张静态图片。相机不可用或相机权限被拒绝时，该入口仍可使用；
相册选择本身不申请相机或全相册读取权限。进入扫码页时原有的相机权限请求仍会执行。
桌面端尚未开放该扫码页，本轮不扩大桌面或 iOS 支持范围。

- 选择图片前取消当前相机拍照/解码任务并停用预览，选择和解码期间拒绝重复点击。
- 普通二维码与相机结果走同一导入回调；QRS 图片与相机共用帧累积器，可以逐张补充帧。
  本轮不实现动画图片逐帧扫描或一次选择多张图片。
- 取消选择保留表单和已收集 QRS 帧；读取失败、未识别到二维码时反馈错误并允许重试。
  如果此前正在扫描相机，取消、失败或尚未集齐 QRS 帧后恢复扫描。
- 选择器和识别任务归扫码页所有，离开页面取消在途等待；迟到的相机/解码结果不能触发导入。
  实际配置导入继续使用既有的导入路径。

选中的 HUI `FileReference` 通过平台载荷交给 Java，持有 provider 引用直至工作线程结束；
通过 `ContentResolver` 流式读取尺寸和采样图像，不把相册原文件整份复制到 C++/JNI 字节数组。
相机 JPEG 和相册图片采用同一条路径。Java 将最长边采样至 1600 像素以内，透明位图
先合成到白底，再将 RGBA 像素与行步长通过 JNI 交给 Lib-QRCode 的 `Decode()`。
识别结果按 UTF-8 返回，识别完成或失败后释放像素锁、位图与文件引用。取消后底层已开始的
读取或识别可能继续到结束，回调会丢弃结果。

分享单码和 QRS 帧由固定的 Lib-QRCode `4f67b7a1b60d459a53effe52af1ca9e44f67ff28`
编码并绘制，内置 ZXing-C++ 3.1.1。分享布局消费弹窗实际可用宽高（上限 300 pt），
按符号总模块数对齐整数缩放，消除固定画布在缩放或窄窗约束后剩下的白边；弹窗不再叠加内容内边距，使用 4 pt
小圆角，避免最小模块尺寸时裁掉定位图案。符号自身保留完整四模块静区和白底黑码。
QRS 在工作线程准备下一张，单帧至少显示 350 ms，弹窗边长以首帧为准保持稳定。
QiFi/QRS 分帧和重组由应用完成。

## 添加配置的识别与返回

应用自带的 QRS 分享使用上述同一编解码器，集齐帧后恢复完整配置字节，按本地配置导入；
不会把单帧 Base64 当作订阅链接下载。普通 HTTP(S) 或兼容客户端唤醒链接仍走远程导入。

二维码与文件入口各有独立忙态，同一入口拒绝重复点击，另一入口不被误标为加载中。
URL/PPTP 创建表单的忙态也归当前实例，不随公共草稿传给下一次打开的页面。
选择文件/相机归页面任务域；已提交的导入归应用任务域，慢下载期间可返回/关闭，
只有未提交的草稿变化需要确认。后台完成仍会更新订阅列表并反馈；返回、卸载或发起
新操作后，旧结果不能再触发页面跳转。下载与存储继续沿用既有任务线程和数据保护路径。

## 依赖与体积

直接消费官方 [Lib-Media 固定源码](https://github.com/HuxerUI/Lib-Media/tree/fee506de40f9763b7374acf394ee0fbfe7f11256)，
URL/完整 SHA 在 `cmake/dependencies/Lock.cmake`，通过 `HuxerUI::Media` 安装并使用
`UseMediaLibrary().PickAsync({MediaFilter::Images, 1})`。未修改上游库或建立 fork。
Android native 与 Java 库图使用同一固定提交，桌面主目标不引入 Media。
2026-11-15 升级仍使用系统单图选择，不启用新增的图库浏览、自建选择器或编解码功能；实际构建见[本轮证据](evidence/2026-11-15-protocol-p2.md)。

该上游版本没有 picker-only 构建开关，Android 库依赖 Media3 ExoPlayer 1.9.3。
应用未创建播放器或播放会话，但构建仍带入播放器依赖；当前应用未启用 R8，
不能假定仅调用图片选择 API 就会剔除所有播放代码。目前保留完整 Media 集成。

## 验证边界

更换编解码库前，已执行主目标/HUI codegen、版本检查、完整桌面 31 项门禁、`qrs_codec`，以及
`platform/android` 中的 `./gradlew :app:assembleDebug`（Java、NDK 与 APK 打包）。
生产 `QrScannerControl` 的无窗口回归覆盖单飞、相册切换取消在途相机任务、
禁止迟到发布、选择结束后重启和页面卸载清理；编解码回归继续覆盖 QRS。

尚未验证真机 Photo Picker/旧版图库回落、云端图片 provider、权限拒绝/返回、
相机恢复、图片识别质量、页面退出时系统选择器表现、实际导入和运行内存。
这些需要设备操作验证，不能由 APK 编译或无窗口回归代替。
