## 实施范围

- P0：冻结 106 组合成输入和预期出站/错误/完整保真度/warnings，位置为 `tests/fixtures/protocol-baseline.json`。覆盖 12 协议的有效样本与未知字段拒绝，以及 HTTP/SOCKS5 的凭据、缺省/空值、TLS、ALPN、指纹、Reality、拨号和错误先后关系。
- P1：HTTP/SOCKS5 通过共享 Clash 字段门控后，进入私有 NodeSpec → 校验 → ValidatedNode → JSON。主订阅和 HTTP/file/inline provider 复用该入口，已删除这两类协议的旧生成分支；失败不尝试旧转换器。
- 模型目前只有 HttpOptions / Socks5Options 两个协议 variant，保留可选凭据、TLS、来源、拨号和 UDP 意图；生成器只消费验证后的模型，不读取 YAML 或 Context。格式适配器按原顺序调用阶段校验，异常抛出前发布已有诊断，避免改变保真度结果。
- 模型测试直接构造节点并注入 Linux 桌面、其它桌面及手机能力组合，验证接口/路由标记限制、detour 的近似记账，以及无 Clash 输入时的 TLS 校验；这不等同这些系统的实机验收。
- VMess 与其 URI、其它十类协议、原生 JSON、组/规则/DNS、持久化和候选提交逻辑保持原有入口。尚未实施 P2–P6，未开放任何新 URI。
