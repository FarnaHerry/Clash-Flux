## 协议实现与等价检查

- VMess/VLESS/Trojan 的 Clash 主订阅、provider 入口进入 NodeSpec → 校验 → ValidatedNode → sing-box 生成器。传输为 Direct/WS/gRPC/HTTP/HTTPUpgrade variant；字段存在性、空列表、零值、false、原文凭据、path/headers、TLS/Reality、UDP 编码和来源默认仍按原语义处理。
- 删除这三类旧 JSON 分支及仅供它们使用的旧 appendTransport/appendProxyUdpEncoding。失败不回退旧实现；其余七类协议仍明确分派到既有实现，原生 JSON 保持 DOM 路径。
- 现有 VMess URI 直接构造协议模型，选择组/MATCH 由单独策略函数生成。主订阅、provider、次来源编排、规则投影和对象目录接入统一路径；不再创建协议 YAML，也未开放新 URI 格式。
- provider 的全表 URI 语法检查仍在筛选前，目标转换仍只检查最终参与节点；选中节点转换失败拒绝整个集合。URI 全局指纹继承、显式覆盖、sourceId/单次记账、原文路径和失败边界有独立生产入口断言。
- 保留 P0 的 106 组冻结样本，新增 P2 的 94 组 Clash 与 17 组 URI，共 **217 组**。200 组 Clash 同时检查主订阅与 inline provider 的输出及完整节点诊断；URI 另查只读语法、MATCH 投影和节点/组/DIRECT 目录。纯模型测试独立构造 VMess/VLESS/Trojan 及传输，验证协议字段隔离、凭据、可选空值和组合拒绝。

P2 冻结基线是已验证 P1 编译器，按 [P1 证据](2026-11-15-protocol-p1.md) 的十一文件顺序、相对路径 + NUL + 内容 + NUL 计算，SHA256 为 `666b7f27899dbfd4c98a341dabce15946e05a250321718d14bb6b14307e4e7de`；本轮最终协议实现为 `12eb77b90049d9d3af6b7c47292bb4b1f8f287cddc4bde7d122daa12ea07bceb`。

保留迁移前静态消费者，迁移后重新链接同一消费者，比较完整 outbounds、数值输出、错误、fidelity 和 warnings：**6000 组 Clash 组合（seed 271828）及 3000 组 URI 组合（seed 314159）全部一致**。URI 差分发现显式 SNI 空白被错误 trim 的反例；修正为原样保留，两个反例由迁移前消费者生成预期后加入冻结样本，没有重录既有预期掩盖差异。临时差分消费者和输入位于 `/tmp/clashflux-protocol-p2`，长期回归依靠仓库 fixture 与模型/生产入口测试。
