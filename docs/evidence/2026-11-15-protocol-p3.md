## 实施范围

- Shadowsocks 的主订阅、HTTP/file/inline provider 及次来源共用 NodeSpec → 校验 → ValidatedNode → sing-box 生成路径，兼容既有 ss/shadowsocks 及大小写类型别名。
- ShadowsocksOptions 保存 method、可选原文 password、专用插件 variant 和可选 UOT。插件仅为无插件、SimpleObfsPlugin、V2RayWebSocketPlugin，不以任意参数字典或已编码字符串作为模型。
- bing.com、WebSocket path /、mux 默认开启、UOT 缺省/显式 0 转 v1 均在 Clash 适配器中解析，模型持有有效值。生成器只编码已验证插件值；反斜杠、分号、等号按固定 SIP003 实现转义一次，百分号和加号保留原文。外层 TLS/V2Ray 传输不能误挂到 SS；simple-obfs 的 TLS 伪装不会开启节点证书 TLS。
- 保留显式 false、空 path、可选空密码、UDP 关闭、未知选项拒绝与诊断顺序。空/缺失密码或不支持 method 原先由固定内核候选检查拒绝的边界保持，映射校验不冒充完整内核批准；冻结样本中的空密码配置仍生成相同 JSON，并实际断言内核拒绝 missing password。
- 删除旧 appendShadowsocksPlugin、appendShadowsocksUot、sip003Escape、专用 JSON headers 助手和旧 SS 生成分支。已迁移协议没有失败回退；原生 JSON、剩余六类协议、数据库/schema、文件提交和下载流程保持。
- 没有新增 SS URI 或其它分享格式；新 URI 适配仍在 P6。

编码依据为固定 [SIP003 参数解析](https://github.com/SagerNet/sing-box/blob/c005f35300ce76427dc285481ec5695f5b179cd2/transport/sip003/args.go) 和 [SS 出站定义](https://github.com/SagerNet/sing-box/blob/c005f35300ce76427dc285481ec5695f5b179cd2/docs/configuration/outbound/shadowsocks.md)。本轮保持既有[插件/UOT 保真度基线](../singbox-layers-and-fidelity.md#shadowsocks-插件与-udp-over-tcp2026-10-02)。

## 真实本地转发

`tests/test_shadowsocks_runtime.py` 使用独占临时目录、回环 HTTP/UDP echo、两个官方固定内核实例：一份真实 SS 服务端，一份消费生产编译器出站的客户端。只替换测试监听端口、控制面与日志，保留编译后的出站及路由；由服务端已解码目标日志确认经过 SS 服务端，UOT 另检查原生协议目标。全部进程/文件均归夹具所有，结束后回收。

| 案例 | 路径与实际检查 |
| --- | --- |
| AEAD aes-256-gcm | 顶层 ss，真实 TCP HTTP 和 UDP 完整字节往返 |
| SS 2022 aes-256-gcm | inline provider 的 shadowsocks 别名，真实 TCP/UDP，32 字节 Base64 密钥原文 |
| UOT v1 | inline provider，服务端仅开 TCP，TCP HTTP + 经 UOT 的 UDP 往返 |
| UOT v2 | 顶层节点，服务端仅开 TCP，TCP HTTP + 经 UOT 的 UDP 往返 |
| UOT false / version 2 | 服务端仅开 UDP，UDP 往返；若误启用 UOT，TCP 入口不存在，测试会失败 |

共 **9 条成功数据流**，证明实际 SS/UOT 转发；插件仍只做模型/冻结/固定内核配置检查，没有远端 simple-obfs 或 v2ray-plugin 握手验收。
