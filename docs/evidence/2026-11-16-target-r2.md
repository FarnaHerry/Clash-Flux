## 当前生产路径

`ProfilesModel` 捕获版本化文件、旧修改、资源目录和资源修订 → 应用任务读取 → `CoreStore::profileTargetSource` 获取来源目标基线 → `ProjectTargetSource` 生成当前目标视图 → 检查输入/任务版本后发布共享快照。转换器不访问数据库、Runtime 或 UI 单例。

来源目标 API 使用固定转换默认和明确资源根，不继承当前模式/TUN/监听/全局策略，不下载、不检查/批准候选、不修改运行计划。旧修改不进入基线：按必要旧锚点重放到实际生成的分支，保留禁用标记、冲突和默认出口。原生未知/复杂字段与数值保留 JSON，省略或 MATCH 之后的来源行不伪装成目标规则。原生空配置的旧隐式兜底锚点单独记录，不能用托管补齐后的 DIRECT 替代旧匹配身份。

应用弱索引核对完整 CompileOptions 与资源修订，同进程固定的转换代码/平台/内核能力是隐含身份，重启不继承。最多 4 个键，键计费 8 MiB；不额外强持有模型。加载在任务线程串行，冷转换取得生命周期锁，与资源发布/回滚同步；调用方先释放该锁再进入索引，顺序为索引 → 生命周期。命中不进入编译器。file/GEO 和未固定正文的 HTTP provider 不保存可复用索引项，重新准备时读取实际依赖；不引入文件监听。

页面快照持有一份原文、目标模型、目标视图、旧修改与目录；首次显式编辑仍按需生成旧编辑投影。编辑目录直接来自目标模型，无第二次出口编译。编辑器升级浅拷贝包装并共享原文/目标，列表引用不可变数据，内存计费在任务线程完成，UI 发布不遍历整张规则表。目录准备期间展示已有只读目标，编辑动作禁用，不重新挂加载骨架。

资源修订进入视图输入身份；手动/周期更新推进修订，资源准备成功重试对应来源。个人修改变化重做目标视图，仍存活且依赖完整的目标基线继续复用。旧个人规则 format_version=1、原文和保存/候选/运行提交路径不改，模型不写入订阅或数据库。

## 内存边界

页面缓存合并原文、输入键、修改/资源目录、目标载荷/描述/出处/诊断、只读投影、懒编辑投影及出口目录的计费，32 MiB 内按最近访问淘汰整个闲置条目。计费是保守估算，不是 allocator 精确测量。在用页面固定数据，最后解除固定后淘汰；在途任务、已持有快照和当前页面不能被撤销，因此可以超预算。输入更新后也执行淘汰，不能只限制规则载荷而无限保留大修改/目录键。

现有候选缓存 32 MiB、provider 转换缓存 32 MiB，加本轮页面 32 MiB、弱索引键 8 MiB，名义保留预算合计 **104 MiB**；另有每个参与线程最多 4 MiB 的旧 YAML 解析缓存。再加用户数据、活动配置、在用/在途结果与分配器开销，不能将合计数字称为进程 RSS 上限，也没有建立全进程统一分配器。R2 后续仍需结合预生成与运行消费者评估共同持有。

10 万条目标模型单体约计费 84.4 MiB，超过页面闲置预算：在用允许持有，离开后会淘汰，重进需要重新转换。未淘汰的页面重进才满足无原文读取/解析；不能承诺所有大小都永久命中。
