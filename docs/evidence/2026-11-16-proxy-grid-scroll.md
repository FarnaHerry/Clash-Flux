# 代理节点网格宽屏滚动

2026-11-16，`71ce44a` 加本修复工作区；HuxerUI `89359f43`，WSL2 Fedora 45 /
Clang 21.1.8 / libc++ / CMake 4.4.2 / Debug，无窗口 `UiTest`。生产卡片与
`PageVirtualGrid` 参数一致（Adaptive 196、估算行高 52、卡片 `ProxyNodeTile`），
5000 个节点，视口 800×1400 或 3200×1400，程序化滚动 96 帧、每帧 160pt。

计时包含测量、布局、扩展、语义、绘制记录和 `UiTest` 结构捕获，**不是** Release、
GPU 呈现或真机 FPS；只用于同环境相对比较。

## 结果

| 视口 | 列数 | 虚拟缓存 | 卡片工厂调用 | p50 | p95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 800×1400 | 3 | 默认（700pt） | 5,668 | 92.3 ms | 451.0 ms |
| 800×1400 | 3 | 200pt | 2,157 | 78.1 ms | 230.0 ms |
| 3200×1400 | 15 | 默认（700pt） | **73,168** | **1,267.6 ms** | **1,636.8 ms** |
| 3200×1400 | 15 | 200pt | 4,112 | 507.0 ms | 651.0 ms |
| 3200×1400 | 10 | 默认（700pt） | 2,580 | 512.2 ms | 628.3 ms |
| 3200×1400 | 7 | 默认（700pt） | 1,806 | 349.8 ms | 428.7 ms |
| 3200×1400 | 7 | 200pt | 1,799 | 236.8 ms | 293.9 ms |

15 列时滚动 96 帧本应只构造约 3.9 千张卡，默认半视口缓存下却发生 7.3 万次
工厂调用：每帧都有大量边界卡片被回收后重新构造，宽屏滚动因此明显卡顿。固定
200pt 缓存后恢复为正常的 4.1 千次。7 列没有该抖动，但 200pt 仍把帧耗时降低约
三成。固定列数实验（15 列 463 ms、8 列 244 ms，均 200pt 缓存、32 帧）说明
每帧成本仍随列数线性增长，列数是剩余上限。

另测 40/24/90+ 字节节点名与单行 `LineLimit(1)`：短名 86.6 ms、全名 88.7 ms、
限长 40 码点 85.9 ms，无可测差异，因此没有保留文本限长改动。

## 修复与边界

- `src/ui/proxies_page.cpp` 给节点网格设置 `CacheExtent(200pt)`：保留约 3 行预热，
  消除宽屏多列时的边界重建抖动，并减少同时挂载的卡片。
- 复现：`test_page_transition --proxy-grid-profile`（Debug 构建，输出
  `proxy-grid-mounted` 与 `proxy-grid-profile` 行）。
- 未验证 Windows/macOS 真机、4K 以上超宽列数、不同 DPI、真实订阅或反向滚动；
  UiTest 绝对耗时不能代替 Release/GPU 验收。
