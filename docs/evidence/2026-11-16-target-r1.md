# 目标工作模型 R1：来源目标捕获

日期：2026-11-16。基线 `f08cde6` 加 R0 和原有 Android HTTP 工作区。R1 新增主来源规则目标快照及捕获，不改 UI、数据库/schema、个人规则持久格式或提交流程。总计划见[目标工作模型](../rule-document-plan.md)，原独立预期见 [R0](2026-11-16-target-r0.md)。

## 接口与所有权

[singbox.cppm](../../src/singbox.cppm) 增加默认 false 的 `CompileOptions.captureTargetSource`；只有显式请求才构造捕获器。成功结果在 `CompileResult.targetSource` 返回 `shared_ptr<const TargetSourceModel>`，普通编译不保留该快照。这里是现有应用模块接口，不是独立库或稳定 SDK。

TargetSourceModel 是拥有型不可变句柄，内部 Data 保存原生 JSON DOM；公开访问器只返回只读描述和已有 SourceObject/FidelityNote，DOM 不泄漏到调用方。规则列表已有原生 action/outbound、已识别字符串匹配字段和值，可直接消费；未知字段、嵌套条件、数值条件及未知动作类型保留在私有载荷中，不据此开放编辑。

`ruleJson(id)` 仅在详情/导出需要时序列化一个原生对象，非法 ID 返回空；`ruleSetsJson()` 输出源局部声明。生成的内核 JSON 不含任何对象 ID、来源锚点、opaque 或启用标记。

| 对象 | 当前语义 |
| --- | --- |
| TargetRule | 只包含实际转换生成的来源规则；ID 在该句柄内唯一，origin 关联出处；不使用内容去重，不承诺跨刷新稳定身份 |
| TargetRuleOrigin | 来源内序号、旧锚点、实际分支 ID 列表、关联诊断索引；Emitted / Default / Omitted / AfterFinal 分开。序号只定位该快照，不是刷新后的编辑 ID |
| synthetic | 标明节点订阅生成的默认策略或推导默认值，不能把生成的 Clash 策略锚点冒充 URI 原文中的规则 |
| TargetDefaultAction | 用 route/outbound 或 reject/method=drop 表达来源默认动作，implicit 表示推导而非显式声明；不把 REJECT 虚构成出站对象 |
| objects | 只收集当前主来源的实际出站/endpoint 目录，tag 为来源局部 tag；不绑定运行命名空间或追加其它来源的对象 |
| diagnostics | 捕获截止时已有的完整来源诊断；每个 origin 的索引指向此快照自己的副本，不借用 Context 内存 |

当前只提供**未叠加个人修改的来源基线**。显式捕获且 options 含个人修改时明确失败，不清空或忽略旧修改；正常编译仍按既有路径执行它们。启用/禁用及修改重放属于 R3；R1 没有把原规则或已禁用来源条目伪装成可编辑目标。OpenVPN/PPTP 不在本批捕获范围，OpenVPN 继续原编译路径且无该快照。

## 捕获位置

实现归 [target/model.inc](../../src/converter/target/model.inc) 与 [target/capture.inc](../../src/converter/target/capture.inc)。后者在同一实现域中连接现有转换器，不重新解析订阅、不重新运行转换器，也不从最终 route.rules 中按位置剥离运行规则。

- Clash/节点订阅：main 的逐条转换包裹现有 convertRule，记录转换前后实际发射范围和诊断范围；合法 MATCH 后的条目仅记录 AfterFinal，保持原有停止行为。非字符串及无法转换的条目不进入目标对象表。
- 默认出口完成现有检查后、namespaceClashSource 之前封存源局部规则、默认动作、目录及 rule_set。REJECT/DROP 的默认动作独立表示，不把最终 JSON 中的拒绝尾规则误认为另一条来源声明。
- 原生 JSON：在托管骨架合并后、运行组合之前捕获原生来源规则。骨架在此阶段补齐默认出口/数组，不注入全局、模式或 sniff/resolve 前置动作；原生复杂对象与 uint64/int64/浮点值不经过缩水模型往返。
- 来源捕获后仍执行次来源、资源和全局/运行策略检查。快照先保存在局部 pending 指针，完整编译成功且未取消才发布到结果；后续失败或取消不暴露部分来源快照。

R0 对 resolve 的描述在这里进一步明确：当前共享 resolve 前置动作来自运行组合，不属于每条 IP-CIDR 的独立生成分支。捕获器只关联真实发射范围，不根据一对多的假设附会出处。默认动作的目标生成表示也须与运行注入分开。

目标规则和引用当前保留源局部名称；它们不是最终运行 tag。规则集声明可能依赖应用准备的资源，快照不提供完整 DNS/节点配置重组、资源快照缓存或内核批准。R2/R3 仍须完成产物身份、总预算、修改兼容及运行绑定，不能单凭此句柄替换完整候选。

## 回归与兼容

新增 [target_source_cases.inc](../../tests/target_source_cases.inc)，合入 singbox 默认 CTest，可单跑 `test_singbox --target-source`。

- R0 的 42 份完整预期保持原 SHA256；独立保存的 R0 消费二进制与新程序对相同 42 输入的观察逐字节相同。
- Linux 下 28 个无个人修改样例对比捕获开/关的 JSON、出站、错误、完整有序 fidelity/warnings、来源对象、参与来源和追溯 plan；其中 26 个成功形成快照，2 个失败不发布快照。另 14 个带旧修改请求明确拒绝基线捕获，普通编译结果仍由 R0 样例验证。
- 手写断言检查源局部默认出口/目录、重复规则不同 ID 与重复旧锚点、MATCH/省略/终止映射、诊断索引、合成节点策略、inline rule_set、原生未知数组/复杂对象及整数边界、非法 action 保留且不猜测 route、全局/托管规则不进入基线、后续次来源失败/取消不发布，以及跨编译的快照生命周期。
- 本批不把捕获成功当作内核支持所有原生未知字段；最终原生 check 仍可拒绝它们。未新增输入能力或改变 exact/approx/unsupported 策略。

R1 未实现缓存：开启捕获会复制原生载荷并构造元信息，两次编译保留两份独立快照。10 万条这一负载额外约 0.55 秒、进程峰值增加约 142 MiB；该峰值包含源 DOM、两个编译结果和两个快照，不是单模型常驻大小。默认关闭的数据不构成“零开销”或统计显著性保证；本轮只观察到相近量级，没有宣称性能提升。

这项成本决定 R2 必须共享同一产物、合并文档/快照/候选的总预算并评估淘汰；不能逐页面复制或直接常驻所有大来源。测量为 Linux Clang 21 Debug 无窗口观察，不外推 Release、GUI 或 Android 真机，不设 CI 墙钟阈值。`opaque=false` 也不表示对象可编辑或已经通过内核能力校验。
