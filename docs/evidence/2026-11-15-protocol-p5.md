## 收敛结果

- `singbox_protocol_parse.inc` 接管 Clash 节点的字段/布尔/凭据/端口门控，嵌套白名单复用 ReadFieldsSupported。删除装配层的 proxyValueInvalid、proxyFieldsSupported、proxyBooleansValid、proxyFingerprintSupported 等重复助手；未知类型由格式适配器明确拒绝，诊断先后及内容保持。
- `convertProxy` 与 `convertProtocolNode` 仅处理格式桥接和来源内名称检查，共同进入 `emitProtocolNode`。生产装配层只保留一处 ValidateNode 调用及一处 EmitSingBox 调用，统一校验、诊断发布和生成；YAML 异常前产生的诊断仍完整发布，不留失败回退或生产双编译。
- SourceDefaults 的未决指纹在模型校验时按所属来源解析；Clash 格式适配器保留较早阶段的指纹检查以保持错误前缀，最终校验复用同一语义且不重复记近似。QUIC 不解析 TCP uTLS 继承；纯模型直接构造也遵守相同能力边界。
- 当前 12 类已有 Clash 协议与现有 VMess URI 完成统一模型、校验、生成和入口核对；模型没有 YAML/JSON 逃生字段，不改公开 singbox API、持久化数据、下载/文件提交、来源身份或手机编排能力。

## 入口核对表

| 入口 | 实际路径与保留边界 |
| --- | --- |
| 普通 Clash 主来源 | compileConfig → compileClashDocument → convertProxy → 格式适配器 → 共同模型出口；普通坏节点仍跳过并记账，坏 MATCH/引用按既有规则使候选失败 |
| 现有 VMess 节点列表 | 有界解包/parseNodeSubscription → NodeSpec → convertProtocolNode → 共同出口；YAML root 只承载选择组/MATCH，没有协议节点；任何坏行仍拒绝整份 |
| HTTP/file/inline proxy-provider | appendProxyProviderNodes 保留原集合语法、筛选次序和参与节点整份失败边界；YAML/现有 URI 分别适配，统一进入共同出口；URI 全表语法检查仍早于筛选 |
| ValidateHttpProxyProvider | 共用上述集合语法/筛选/模型转换，只做资源内容检查；不联网、不写文件，也不替代引用/DNS/完整候选与内核批准 |
| 桌面次来源 | compileAuxiliarySources → 独立 Context → compileClashDocument(exportOnly) → 同一节点出口；默认值按来源隔离，现有命名空间和组/detour/DNS 依赖闭包保持 |
| 激活前对象目录 | inspectProfileSourceObjects → compileClashDocument(exportOnly)；需要稳定 source ID，保留节点身份和账本，返回 JSON 为空，不发布运行计划或提交资源 |
| 文档检查 | DetectProfileFormat / ValidateProfileDocument；检查完整格式/顶层结构，VMess 逐行格式仍解析；不把普通 Clash 的文档可读等同于每个协议受支持 |
| 只读规则投影 | InspectProfileRules 对 Clash 使用既有规则事件投影及 YAML 回落，VMess 读取单独生成的选择策略，原生 JSON 使用 DOM；不绕回临时 Clash 协议节点、不新增完整运行编译 |
| 原生 sing-box JSON | compileConfig 的独立 DOM 分支，保留原生节点及未知字段/数值类型，再按既有约定合并托管配置；不往返到不完整协议模型；原生次来源与 Clash 对象目录仍未开放 |
| Runtime / 预览 / 导入与刷新消费方 | 继续调用现有 compileConfig / Prepare、文档和目录 API；本轮未改 store/CLI/数据库/候选提交，失败保留和迟到结果保护由原有生产门禁回归覆盖 |

## 单列修复：provider 的 VMess TLS 别名漏账

P4 的主节点订阅会为非标准 `net=tls` → TCP+TLS 记 `Node/Approx`，HTTP/file provider 使用相同解析结果时漏了该说明。本轮保留既有映射、输入与拒绝范围，仅补齐参与节点的相同说明、sourceId 和 warnings 投影；被筛选掉的别名节点不进入账本，别名说明先于后续模型错误/指纹近似发布。

main 与 provider 复用 noteNodeSubscriptionTlsAlias；provider 在完整 URI 语法检查和筛选后发布参与别名，之后仍经共同模型出口。该修复的生成 JSON 不变，账本/warnings 增加缺失说明，是明确记录的行为修复，不混作所有入口完全零差分。

将保存的 P4 singbox.cpp 与本轮入口测试在临时目录独立编译/链接，运行 `test-entries-before --protocol-entries`，出现 **8 项预期断言失败**，全部指向 provider 别名/指纹近似；本轮相同测试通过。没有临时替换生产源码或重录冻结预期。对照脚本及日志在 `/tmp/clashflux-protocol-p5/check-old-entries.py`、`old-entries.log`。
