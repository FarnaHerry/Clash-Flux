# 2026-11-15 协议重构 P4：HY1/HY2/TUIC、AnyTLS/Snell/SSH

应用快照为 `894a8080455e066bb63811deb5097554e4c62cdd` 加前序规则/二维码、P0–P3 和本轮未提交工作区。应用版本 v0.3.110、sing-box 1.14.4（`c005f35300ce76427dc285481ec5695f5b179cd2`）、HUI `89359f43`、CodeEditor `ee5b0cf8`、Media `fee506de` 保持；本轮未升级依赖。

## 实施范围

- 分 HY1/HY2/TUIC 与 AnyTLS/Snell/SSH 两批，将剩余六类已有 Clash 协议迁移到专用模型、独立校验与生成器；主订阅及 HTTP/file/inline provider 继续共用节点入口，桌面次来源继续在现有装配层重写命名空间和引用。
- 模型分别承载 HY1 的字节/文本认证 variant、带宽、有效窗口与跳端口，HY2 的无混淆/Salamander/Gecko variant，TUIC 的认证、拥塞和 0-RTT 意图，AnyTLS 的会话/metadata，显式 Snell4 类型与伪装，SSH 的原文用户/密码/内联私钥及有序公钥偏好。NodeSpec 的单端口改为可选；HY 的有效端口范围另存，不为 ports-only 构造假端口。
- Clash 单位、默认窗口、别名/字段优先级和区间语法留在格式适配器；校验器拒绝无效模型组合，生成器仅消费 ValidatedNode，不再读取 YAML/Context。QUIC TLS 不继承 TCP uTLS；AnyTLS 保留 TCP TLS 指纹；SSH/Snell 不生成外层 TLS，Snell TLS 伪装仍是其专用字段。
- 保留 TLS 验证默认、显式 false/0/空值、HY1 Base64 原文字节与 auth 优先级、端口/时间上限、AnyTLS 固定 TCP/UDP 的近似记账、SSH 双认证顺序差异及完整诊断顺序。AnyTLS UDP 近似在拨号错误前发布且不会重复，SSH UDP 近似仍在拨号检查后发布。
- 删除旧 HY/AnyTLS/Snell/SSH 节点 JSON 分支、appendTls、appendProxyDialer、appendSshOptions、HY 带宽/认证/端口辅助实现。当前 12 类 Clash 协议统一走 NodeSpec → 校验 → ValidatedNode → sing-box 生成，无失败回退旧实现。
- 本轮保持既有接受范围，包括 Snell `obfs-opts.mode` 的缺省/异常标量回落为空模式、`host` 回落到 bing.com，以及 TUIC 拥塞字段的既有标量回落；冻结样本明确覆盖这些旧行为。如需收紧，须另立行为修复及预期，不能把它混进等价迁移。
- 原生 JSON DOM、下载/文件提交、数据库/schema、来源身份、现有 VMess URI 范围均保持；P5 入口总核对和 P6 新 URI 格式尚未实施。

字段语义继续以[协议保真度基线](../singbox-layers-and-fidelity.md#41-出站协议clash-转换覆盖-12--15-个代理协议类型)为准。本地服务端使用固定内核的 [HY1](https://github.com/SagerNet/sing-box/blob/c005f35300ce76427dc285481ec5695f5b179cd2/docs/configuration/inbound/hysteria.md)、[HY2](https://github.com/SagerNet/sing-box/blob/c005f35300ce76427dc285481ec5695f5b179cd2/docs/configuration/inbound/hysteria2.md)、[TUIC](https://github.com/SagerNet/sing-box/blob/c005f35300ce76427dc285481ec5695f5b179cd2/docs/configuration/inbound/tuic.md)、[AnyTLS](https://github.com/SagerNet/sing-box/blob/c005f35300ce76427dc285481ec5695f5b179cd2/docs/configuration/inbound/anytls.md) 和 [Snell](https://github.com/SagerNet/sing-box/blob/c005f35300ce76427dc285481ec5695f5b179cd2/docs/configuration/inbound/snell.md) 定义；Snell 服务端 v5 的非 QUIC 协议兼容 v4，不据此新增 Clash v5 输入支持。

## 真实本地转发

`tests/test_protocol_runtime.py` 已纳入 CMake 必跑门禁，使用独占临时目录、回环 HTTP/UDP echo 和两个官方固定内核实例。客户端消费生产 `--compile-config` 结果，仅替换夹具监听/控制面/日志并加入夹具私有证书信任；保留协议、路由和编译后的 server_name。TLS 保持验证开启，无 insecure，根证书不进入系统或生产配置。全部进程与文件由夹具拥有并回收。

| 场景 | 实际流量与关键字段 |
| --- | --- |
| HY1 | 字节 auth 优先于 auth-str，带宽 MBps、显式窗口、XPlus、ports-only 单端口范围，TCP/UDP |
| HY2 Gecko | inline provider、原文密码、显式零 packet size、ports-only 与跳端口时间范围，TCP/UDP |
| HY2 Salamander | 顶层节点、独立混淆密码，TCP/UDP |
| TUIC | inline provider、bbr、h3 ALPN、显式 false 的 disable-SNI/0-RTT，TCP/UDP |
| AnyTLS | 原文 metadata、显式零空闲会话数、默认验证的 TCP TLS/uTLS，TCP/UDP |
| Snell v4 plain / HTTP | 两场景分别为顶层/provider，PSK 原文与 reuse，固定原生 v5 兼容服务端，TCP/UDP |

共 **14 条成功数据流**；每项检查客户端完整响应与服务端协议入口/目标日志。另以同一私有信任根和错误 server_name 验证 **TLS 身份拒绝**，同时断言原生证书错误与 HTTP 目标请求数不变，不能以连接超时当作证书验证证据。此处 ports-only 是单端口范围，未覆盖长时间跨多端口切换。

SSH 另完成本地手工补充检查：`python3 /tmp/clashflux-protocol-p4/ssh-runtime.py` 用已缓存 x/crypto v0.54.0 编译独占回环 SSH 服务端，消费仓库专门生成的公开样本密钥；固定原生客户端仍消费生产编译结果。**密码、带原文 passphrase 的加密私钥、双认证三条 TCP 转发成功**，双认证从服务端确认密码先于私钥。错误主机公钥在认证前拒绝，服务端认证记录与 HTTP 请求数均不变。该夹具不属于 CI 必跑、不引入应用/CI Go 依赖、不使用系统账号或修改 sshd；仓库的 SSH 长期回归仍为冻结、纯模型及固定内核配置检查。合计本轮手工加必跑覆盖 17 条成功数据流、TLS 身份与 SSH 主机公钥两类拒绝。
