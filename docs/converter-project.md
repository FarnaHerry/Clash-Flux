# 转换子项目的发展与结构

日期：2026-11-15。决策：**将转换层作为可复用、可独立维护的项目持续发展，当前留在 Clash-Flux 仓库内，共用现有构建和发布。** 本轮先整理源码归属、文档入口和依赖边界；独立仓库、库目标、安装包及稳定 SDK 均是后续按需推进的工作。

2026-11-16 方向细化：下一步建设[sing-box 目标工作模型](rule-document-plan.md)，以转换结果作为交互基线，内容贴近 sing-box，来源/启用/用户修改等管理信息独立附挂；规则页复用目标产物，不再自行重解析订阅。原文仍保留为输入和刷新基线，不建设另一套完整来源编辑树。R0/R1 已完成；R2 已接入共享目标快照、只读规则页与编辑目录，保留旧修改兼容重放，预生成已接入，编辑/预览/运行贯通仍有后续工作；重启加载与磁盘产物单独评估。

## 目标与当前状态

转换子项目负责输入解析、协议语义、目标能力校验、配置生成及结构化保真度。Clash-Flux 作为调用方，提供来源内容、用户意图、资源快照和目标环境，接收候选配置、诊断、资源需求及对象目录。

P0–P6 已完成的协议重构和 URI 扩展是这个方向的基础，原阶段结果见[重构计划](protocol-refactor-plan.md)；它们不等于已经完成独立库封装。当前 NodeSpec 等仍是私有类型，诊断引用现有 FidelityNote，完整 CompileOptions/CompileResult 还包含应用的网络、VPN、个人规则、缓存和追溯类型；部分配置编译仍直接读取文件。

`test_singbox` 已可在不链接 HUI、不启动 GUI 的条件下运行转换回归，但仍使用同仓模块、头文件和顶层构建。现有 `clashflux.singbox` 继续作为集成接口；没有独立项目的外部消费者构建或发布验收。

## 责任划分

| 归属 | 发展方向与边界 |
| --- | --- |
| 通用转换核心 | 格式识别/有界解包、URI/Clash 适配、中立协议模型、TLS/传输/凭据校验、目标配置生成、exact/approx/unsupported 诊断、输入能力登记 |
| 通用配置编译 | 逐步整理组/DNS/规则/provider 的转换、引用检查、依赖图和可复用对象目录；当前部分仍在 src/singbox_*.inc，不以目录位置宣称已经解除产品耦合 |
| Clash-Flux 适配 | 将应用设置、个人/全局策略、来源选择和平台事实转换成编译输入；把结果绑定到当前 profile、预览和运行计划，保持既有命名空间、引用与错误策略 |
| Clash-Flux 运行与存储 | 下载/刷新调度、缓存所有权与提交、数据库、原文落盘、候选批准/回滚、服务/libbox 启停、系统网络权限、UI/CLI 交互 |

转换代码不依赖 UI、DataSession、CoreStore 或 Runtime 的单例来获取输入，不在格式解析/生成中启动下载、内核或修改系统设置。来源 ID 可作为调用方提供的不透明标识传递，核心不查询其数据库含义。文件/缓存读取的现有实现先明确归属，后续再以资源快照或显式资源接口收敛；不借整理目录修改已批准缓存、原文或提交事务。

应用策略可以进入配置编译，但通过明确的输入契约传入，避免把活动来源、当前设置或手机/桌面状态变成解析器的隐式默认。已有的来源隔离、平台能力、候选失败保护和保真度规则继续执行。

## 当前目录与编译方式

```text
src/converter/
  README.md                 源码导航与维护入口
  protocol/
    model.inc               拥有型协议、TLS、传输和目标上下文
    clash.inc               Clash 节点适配与格式默认
    validate.inc            协议/目标校验与诊断
    singbox.inc             已验证节点的 sing-box 生成
  target/
    model.inc               来源目标对象、私有载荷及内存计费
    capture.inc             实际生成分支、默认、出处与诊断捕获
    project.inc             目标只读视图与旧修改兼容重放
  input/
    subscription.inc        列表解包/分流/名称与默认策略装配
    catalog.inc             输入登记和经审查的内核身份
    uri.inc                 公共 URI 语法与 SIP002
    legacy_ss.inc           历史 SS 原文凭据适配
    v2ray.inc               VLESS/Trojan
    secure.inc              HY2/TUIC/AnyTLS

src/singbox.cppm             现有应用公开接口
src/singbox.cpp              现有实现单元和装配入口
src/singbox_*.inc            待逐步整理的配置/资源/应用集成代码
```

本轮十个实现片段仅移动目录、调整 include 与 Android 依赖登记，保持同一模块、同一实现域及原有包含顺序。VMess JSON 和默认策略装配仍在 input/subscription.inc，后续可按实际边界继续细分，不为目录对称增加抽象或重复实现。

目录说明见 [src/converter/README.md](../src/converter/README.md)。既有纯模型、公开入口、冻结样例、能力清单和固定内核运行测试继续复用；测试暂不搬迁，也不增加第二套预期。历史证据的路径清单及源码指纹保持原快照含义，可点击的源码链接转到当前位置。

当前仅生产 sing-box 后端。中立模型保留发展空间，不因此承诺其它目标、完整原生 JSON 模型化、所有分享格式或各平台全部能力。完整原生 JSON 仍保留既有 DOM 路径，不能用不完整模型往返丢字段。

## 维护与验收

- 新增通用转换逻辑优先归入 src/converter；对应用类型/状态的新增依赖先说明归属，避免继续扩大待拆边界。
- 外部 API 按实际消费者需求设计，保持拥有型数据和结构化诊断；不因项目方向提前导出内部 NodeSpec、承诺稳定 ABI、建立 IR 持久化或增加通用扩展字典。
- 当前 CMake/CPS 及依赖版本保持；独立库建立前继续使用原模块入口，不能让应用和子项目各维护一套转换器。
- 支持矩阵只维护在[保真度契约](singbox-layers-and-fidelity.md)与[节点订阅](node-subscriptions.md)；能力登记、审查内核身份和独立预期必须一致，整理结构不收紧/放宽输入或改错误先后。
- 目录移动先核对内容与 include 顺序，运行现有回归；Android 同步 AndroidLegacy 依赖并实际编译。独立构建、跨平台、GUI、VPN 和发布验收分开记录，不能用一次目录归拢宣称全部完成。

执行入口见[编译器技能](../project-skills/clashflux-compiler/SKILL.md)、[测试技能](../project-skills/clashflux-test/SKILL.md)和[依赖技能](../project-skills/clashflux-dependencies/SKILL.md)。本轮实际状态与检查记录在[L1/L2/L3 状态](l1-l2-l3-status.md)，P0–P6 的既有行为约束继续生效。
